# 缺陷修复报告模板

```markdown
# 缺陷修复报告：{缺陷ID}

## 基本信息
- **发现时间**: {YYYY-MM-DD HH:MM}
- **修复级别**: 子变更级
- **发现阶段**: {测试轮次或其他}
- **缺陷类型**: {功能缺陷|UI缺陷|性能问题|其他}
- **根因分类**: {实现错误|测试错误|设计错误}
- **严重程度**: {高|中|低}
- **复现率**: {≥ 50% / 1-50% / < 1% / 确定性}

## 缺陷描述
### 触发条件
{复现步骤}
### 预期行为
{预期结果}
### 实际行为
{实际结果}
### 错误信息
{错误日志、堆栈追踪等}

## Feedback Loop
### 使用的方法
{优先级 N: 方法名} — {✅ 成功 / ❌ 失败}
### Loop 描述
{可运行的 pass/fail 检测方式}

## 假设列表
| 序号 | 假设（可证伪格式） | 测试结果 | 验证结论 |
|------|-------------------|---------|---------|
| 1 | 如果 X 是原因，则改变 Y 会让 bug 消失 | ✅ | ✅ 正确 |
| 2 | 如果 A 是原因，则改变 B 会让 bug 消失 | ❌ | ❌ 错误 |

## 根因分析
### 分类结论
{实现错误 / 测试错误 / 设计错误}
### 分析过程
{决策树路径}
### 根因结论
{根因描述}

## 修复方案
### 路由决策
{修复代码 / 修正测试 / 触发阶段回退}
### Regression Test Seam
{seam 正确性评估：✅ 正确 / ⚠️ 无正确 seam — 已记录}
### 代码变更
{变更文件列表和关键变更内容}

## 验证结果
### 本地验证
- 验证时间: {时间}
- 验证方法: {方法}
- 验证结果: ✅ 通过
### 原始场景验证
- 重新运行 feedback loop: ✅ 通过

## Post-mortem
### 复盘结论
{什么可以防止此缺陷发生？}
### 架构改进建议
{改进建议，如无则写"无架构改进建议"}
### 最终正确的假设
{假设序号 + 为什么正确 + 为什么备选假设被排除}
### 调试日志清理
- [x] 调试 instrumentation 已清理
- [x] throwaway prototype 已清理
- [x] 临时文件已清理

## 状态
- [x] Feedback loop 构建完成
- [x] 缺陷复现完成
- [x] 假设验证完成
- [x] 根因分类完成
- [x] 分析完成
- [x] Regression test seam 评估完成
- [x] 修复完成
- [x] 本地验证通过
- [x] Post-mortem 完成
- [ ] 测试阶段验证（待新一轮测试）
```
