# 自循环审查 — 维度与规则（签署清单 + 单轮验证）

> **v4.0.0 变更**: 自审终止模型由「多轮收敛循环」改为**固定单轮**——主 Agent 先在写作阶段按 4 维度签署清单自证（零子代理），随后**一轮**独立子代理验证打假，主 Agent 统一修复后直接交付下游。删除多轮循环的收敛判据、失败终止判定、跨轮摘要注入与跨轮修复清单。验证子代理改为**只报告不修改产物**（审查者与修复者分离）。自审报告由「每轮一份时间戳文件」改为固定一份 `self-reviews/explore/report.md`。终止结果由旧二值改为 `验证通过` / `验证发现问题({N})`。权威定义见 self-review.md §3~§5 与 `signed-checklist-verification` 能力。
>
> **v3.0.0 变更**: 终止模型曾调整为多轮收敛循环（该模型已被 v4.0.0 取代）。
>
> **v2.2.0 变更**: 自审执行方式从"当前 Agent 自身执行"改为"子代理（Agent subagent）执行"。子代理拥有独立上下文，按维度检查，生成审查报告。
>
> **v2.1.0 变更**: 从"分工制"改为"重复制"——每次执行覆盖全部四个维度（完整性+闭环性+必要性+清晰性）。该原则在单轮模型下继续成立：单轮 SHALL 覆盖全部四个维度，SHALL NOT 将维度分组到不同执行批次。

## 审查维度与检查规则

### 完整性

| 检查项 | 规则 |
|--------|------|
| 页面覆盖 | 是否所有用户可见页面均已覆盖 |
| 菜单覆盖 | 是否所有菜单路径均有对应功能点 |
| 操作覆盖 | 是否所有用户可执行操作均有对应功能点 |
| 表单项覆盖 | 是否所有涉及表单输入的功能点均有完整表单项定义 |

### 闭环性

| 检查项 | 规则 |
|--------|------|
| 流程完整性 | 每个业务流程是否从触发点到最终结果形成完整路径 |
| 断点检测 | 检查是否存在"无处可去"的中间状态 |
| 异常路径 | 业务流程中的分支条件和异常路径是否已标注 |

### 必要性

| 检查项 | 规则 |
|--------|------|
| 多余功能点 | 检查是否存在无明确用户价值的功能点 |
| 冗余功能点 | 检查是否存在功能重叠的功能点 |
| 价值验证 | 每个功能点是否有明确的用户价值描述 |

### 清晰性

| 检查项 | 规则 |
|--------|------|
| 描述无歧义 | 每个功能点描述是否无歧义 |
| 边界明确 | 每个功能点的输入/输出边界是否清晰定义 |
| 术语一致 | 功能点描述中使用的术语是否与 CONTEXT.md 定义一致 |

## 单轮验证执行流程

```
单轮验证执行流程:

1. 读取变更级 .status.md「变更档位」字段（缺失按 完整 档处理；详见 self-review.md §7）
   └── 档位只决定审查形态与产出深度，SHALL NOT 决定轮数（轮数恒为 1）
2. 主 Agent 在产物写作阶段按完整性、闭环性、必要性、清晰性四个维度
   逐项完成**签署自证**（零子代理），填写「维度 / 自证结论 / 证据锚点」
   └── 证据锚点 SHALL 指向 functional-designs/ 内的具体位置
       （章节号、功能点 ID `FP-00N`、表名之一）；锚点为空或指向不存在内容 = 签署不成立
   └── 某维度自证不通过 → 先修复该产物 → 重新自证该维度
3. 主 Agent 从 functional-designs/ 既有产物生成**审查对象清单**并冻结，
   注入子代理 prompt；审查维度限于完整性、闭环性、必要性、清晰性四个枚举
   └── 轻量档同样 SHALL 启动验证子代理并产出 `self-reviews/explore/report.md`，
       产物完整性门控（functional-designs/ 产物全部存在且无占位符）保留为附加硬门
4. 主 Agent 启动验证子代理:
   Agent(
     subagent_type="claude",
     description="Explore 单轮验证",
     prompt="第一步：独立遍历 functional-designs/ 下的所有产物文件，按完整性、闭环性、必要性、清晰性四个维度形成你自己的结论——此阶段 SHALL NOT 读取签署清单。第二步：逐项对照产物中的签署清单执行打假，判定每项签署是否属实（证据锚点为空或指向不存在内容 = 该维度签署不成立）。审查对象集合已冻结——SHALL NOT 审查清单之外的产物或文件、SHALL NOT 新增审查维度、SHALL NOT 借审查之名新增功能点/字段/章节。SHALL NOT 修改任何产物文件，只将问题记入报告。输出验证报告到 self-reviews/explore/report.md，包含：签署清单打假结果（维度名/自证结论/证据锚点/打假结论/不成立原因）、独立发现问题清单（序号/问题描述/严重度/所属维度）、范围外观察（为空记『（空）』）、全量遍历证明、验证结论（发现总数 N 与终止结果）。冻结范围之外发现的问题 SHALL 记为『范围外观察』——SHALL NOT 计入验证发现数、SHALL NOT 触发产物修改。"
   )
5. 子代理返回验证报告路径
6. 主 Agent 读取报告：
   ├── 校验审查对象是否超出冻结范围；超出时 SHALL 拒收并要求子代理在冻结范围内重新验证，
   │   并将越界事实记录到 docs/skill-suggestion.md
   ├── 汇总「范围外观察」条目，在阶段终止时向用户提示
   └── 汇总发现总数 N
7. 主 Agent **统一修复**全部发现项，生成「本阶段修复清单」随产物交付下游
   └── SHALL NOT 追加确认轮；修复结果的独立验证由交叉审查（REVIEW）承担
8. 终止时写入 .status.md 终止结果（`验证通过` / `验证发现问题({N})`）
9. 终止后标记阶段完成，释放 prototype 或 design 阶段门控
```

## 报告责任与产物修改的分离

验证子代理 SHALL NOT 修改任何产物文件——发现问题只记入验证报告：

- 全部发现项由**主 Agent** 在验证完成后统一修复
- 修复范围仅限于验证报告确认的问题，不做重构或额外改进
- SHALL NOT 新增功能（遵循"非必要不增加新功能"原则）
- SHALL NOT 新增冻结审查对象集合之外的产物内容（功能点、字段、章节、分支）
- 冻结范围之外发现的问题 SHALL 记为「范围外观察」写入报告，SHALL NOT 触发修改
- 该分离消除「边审边修又改出新问题」的振荡源

## 单轮约束

- 轮数恒为 1——SHALL NOT 预置轮数、SHALL NOT 执行第二轮、SHALL NOT 存在 0 轮豁免路径
- 单轮 SHALL 覆盖完整性、闭环性、必要性、清晰性**全部四个维度**的完整检查，SHALL NOT 将维度分组、SHALL NOT 新增审查维度
- 验证子代理执行顺序强制为「先独立遍历后打假」，顺序反转时该轮结果 SHALL NOT 被接受
- 验证子代理 SHALL NOT 修改产物，只报告
- 不追加确认轮；修复结果由交叉审查验证

## 验证报告内容

验证报告（`self-reviews/explore/report.md`，固定一份）包含：

| 报告要素 | 说明 |
|---------|------|
| 签署清单打假结果 | 维度名、自证结论、证据锚点、打假结论（属实 / 不成立）、不成立原因 |
| 独立发现问题清单 | 序号、问题描述、严重度、所属维度（来自「先独立遍历」步骤，与签署清单对照结果分开呈现） |
| 范围外观察 | 冻结审查对象集合之外发现的条目；无条目时记「（空）」（不改产物、不计入发现数） |
| 全量遍历证明 | 显式声明全部 4 个维度与全部审查对象均已完成遍历 |
| 验证结论 | 发现总数 N；终止结果 `验证通过` 或 `验证发现问题({N})` |

> **反空转**：未证明全量遍历的报告 SHALL 判定为不完整，主 Agent SHALL 要求子代理补齐后重新提交。

## 强制执行规则

- 轮数恒为 1，SHALL NOT 存在 0 轮豁免路径；SHALL NOT 因该轮发现问题而自动执行第二轮
- 轻量档 SHALL 执行完整的单轮验证（启动验证子代理、产出 `self-reviews/explore/report.md`）；产物完整性门控保留为附加硬门
- 签署自证 SHALL 由主 Agent 执行（零子代理）；签署清单 3 列且证据锚点须指向产物内具体位置，锚点为空或指向不存在内容时该维度签署不成立
- 审查对象集合 SHALL 由主 Agent 从阶段产物既有内容生成并冻结，审查维度限于四个枚举；子代理 SHALL NOT 扩大审查对象集合、SHALL NOT 新增审查维度
- 冻结范围之外的发现 SHALL 记为「范围外观察」，SHALL NOT 触发产物修改、SHALL NOT 计入验证发现数；子代理引入冻结范围外新内容时 SHALL 拒收该轮并要求在冻结范围内重新验证
- 验证子代理 SHALL NOT 修改任何产物；全部发现项由主 Agent 统一修复
- 不追加确认轮
- 终止时 SHALL 写入 .status.md 终止结果（`验证通过` / `验证发现问题({N})`）；读取侧遇历史 `收敛` 取值 SHALL 归并为 `验证通过`
- 主 Agent SHALL 在阶段终止时汇总「范围外观察」条目并向用户提示
- 验证子代理异常（意外停止 / 报错退出 / 返回不完整结果）时，主代理 MUST 重新创建新子代理，SHALL NOT 接管；最多重试 3 次，全部失败后标记 ⚠️ 阻塞并提示用户
- 自审终止后标记阶段完成，释放 prototype 或 design 阶段门控
