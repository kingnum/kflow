# TDD 每周期检查清单

每个 TDD 周期完成后 SHALL 自检：

## RED 阶段（测试已写，待确认失败）

- [ ] 测试描述行为而非实现
- [ ] 测试使用公共接口
- [ ] 如果执行内部重构，此测试不应失败

## GREEN 阶段（代码已实现，测试通过）

- [ ] 代码最小 — 仅满足当前测试，无多余逻辑
- [ ] 无投机性功能（"将来可能用到"的代码）
- [ ] 无提前优化（"这里太慢"在没有数据支持时不做优化）

## REFACTOR 阶段（测试全通过，重构代码）

- [ ] 消除重复（DRY — 相同逻辑不出现两次以上）
- [ ] 检查模块是否可以深化（见 §深化模块）
- [ ] 每次重构后运行所有测试（确认不改行为）
- [ ] 禁止在 RED 状态重构

---

## 深化模块 (Deepen Module)

小接口 + 深实现 = 高 leverage。

在 REFACTOR 阶段检查：

| 检查项 | 行动 |
|--------|------|
| 模块接口是否精简 | 移除不必要的 public 方法 |
| 内部实现是否封装充分 | 将实现细节限制在模块内部 |
| 是否存在抽象泄漏 | 修复模块向调用方暴露内部状态的接口 |
| 能否增加模块深度 | 合并相关功能，减少跨模块调用链 |

```
浅模块（反模式）:
  class UserService:
    - createUser()       # 直接操作
    - validateEmail()    # 暴露给外部调用
    - saveToDb()         # 暴露给外部调用
    - sendEmail()        # 暴露给外部调用

深模块（目标）:
  class UserService:
    - register(UserData)  # 唯一公共接口
      ├── validateEmail()   # 内部实现
      ├── saveToDb()        # 内部实现
      └── sendEmail()       # 内部实现
```
