# 角色

变更级集成测试执行器。所有子变更完成后执行跨子变更集成测试，验证接口契约和端到端流程。内聚四分法缺陷修复循环，不委托给 `kflow-bug-fix`。适用于前后端和纯后端项目。

变更档位为 `轻量` 且阶段适用性声明判定为 `⏭️ 不适用`（有判定依据）时，本 Skill SHALL NOT 启动，SHALL 直接进入审计阶段（见「阶段适用性入口门控」）。`标准` 与 `完整` 档 SHALL NOT 应用该机制。

> ⚠ **子代理强制规则**（参见 skills/kflow-integration-test/references/repetition.md §12）:
> 1. 本阶段主工作 MUST 通过 Agent 子代理执行，主 Agent 仅负责调度和验收
> 2. 主 Agent SHALL NOT 直接执行本阶段主工作，无例外
> 3. 子代理 SHOULD 前台运行（推荐 `run_in_background=false`），后台模式仅在权限已预配置时使用
> 4. 适用场景：直接触发 + triage 路由 + 其他 Skill 调用
> 5. 后台子代理权限失败时 SHALL 创建新的前台子代理重新执行，主 Agent SHALL NOT 直接接管（参见 §12.7）

# 任务

门控检查（子变更全部完成 + 服务刷新）→ 等待服务就绪 → 读取集成测试用例 → 执行集成测试 → 输出轮次报告 → 评估结果 → 四分法根因分类 → 修复循环（内聚）→ 架构评估自动触发（连续3轮同用例失败）→ 服务崩溃恢复 → 循环直到全部通过 → 输出总结报告 → 更新状态。

# 门控检查

进入集成测试阶段前检查：
- 阶段适用性声明按四态判定（仅轻量档，见「阶段适用性入口门控」）
- 所有子变更编码 + 审查状态 = ✅ 完成
- 所有子变更接口单元测试状态 = ✅ 完成 或 ⏭️ 不适用（有声明依据）
- 前后端项目：所有子变更 E2E 测试状态 = ✅ 完成 或 ⏭️ 不适用（有声明依据）
- 变更级服务刷新已完成并通过（服务编译、迁移执行、重启、健康检查）
- `integration-tests/index.md` 文件存在
- 任一不满足则提示先完成前置条件

> 前置测试阶段的完成判定为「✅ 完成 **或** 已标记 `⏭️ 不适用`（有声明依据）」，轻量档裁剪掉的测试阶段 SHALL 视为满足前置条件。

# 阶段适用性入口门控

> **四态判定矩阵**参见 `skills/kflow-integration-test/references/gates.md` §1.2；**声明字段**参见 `skills/kflow-integration-test/references/state-values.md` §5；**钩子豁免**参见 `skills/kflow-integration-test/references/hooks.md` §1

仅 `变更档位 = 轻量` 时适用，`标准` 与 `完整` 档 SHALL NOT 应用本机制。变更档位读取自变更级 `.status.md` 基本信息，字段缺失时按 `完整` 档处理。

## 适用性判定

判定依据为变更级 `detailed-design.md`：接口设计章节含本变更新增或修改的接口条目，**或**「跨子变更接口契约」章节含本变更条目 → `✅ 适用`；否则 `⏭️ 不适用`。判定依据产物不存在 / 格式不符 / 字段缺失时 SHALL 判为 `✅ 适用`（保守回退）。

## 四态判定

| 阶段适用性声明 | `test-reports/integration/` | 判定 | 处理 |
|--------------|---------------------------|------|------|
| `⏭️ 不适用` | 不存在 | 合法跳过 | 直接进入审计阶段 |
| `⏭️ 不适用` | 存在 | 不一致，❌ 阻塞 | 提示声明与产物矛盾 |
| `✅ 适用` | 存在 | 通过 | 正常执行本阶段 |
| `✅ 适用` | 不存在 | ❌ 阻塞 | 输出缺失产物清单 |

无声明依据的 `⏭️` 一律 ❌ 阻塞。

## 裁准时行为

声明 `⏭️ 不适用`、`test-reports/integration/` 不存在且存在判定依据时：

- SHALL NOT 启动本 Skill，SHALL NOT 创建子代理
- SHALL NOT 执行任何 PRE_HOOK / POST_HOOK 步骤（含变更级服务刷新、编译重启、浏览器清理）
- SHALL NOT 产出 `test-reports/integration/summary.md` 与轮次报告
- SHALL **直接进入审计阶段**，跳过本文件「执行流程」的全部步骤
- 归档门控 SHALL 视为满足

轻量档集成测试仍适用时，按轻量档轮次（1 轮）执行。

# 四分法根因分类

## 分类标准

| 分类 | 占比 | 判定条件 | 处理方式 |
|------|------|---------|---------|
| 接口实现错误 | ~60% | 代码实现不满足接口契约，但契约本身正确 | 定位子变更 → 修复代码 → 子变更重测 → 重新集成 |
| 接口契约错误 | ~20% | 接口契约定义本身有缺陷或不一致 | 更新 detailed-design.md → 评估联动范围 → 修复受影响子变更 → 重新集成 |
| 测试用例错误 | ~15% | 集成测试用例预期与设计不符 | 修正 integration-tests/ → 验证正确性 → 重新集成 |
| 架构设计错误 | ~5% | 架构层面结构性问题 | 标记阻塞 → 触发架构评估 → 用户决策 |

## 修复报告输出路径

| 错误类型 | 报告路径 | 内容要求 |
|---------|---------|---------|
| 接口契约错误 | `test-reports/integration/fix-reports/contract-error-{timestamp}.md` | 契约矛盾点、受影响子变更、修订建议 |
| 架构设计错误 | `test-reports/integration/fix-reports/arch-assessment-{timestamp}.md` | 架构缺陷分析、影响范围、回退建议 |

# 架构评估自动触发

## 触发条件

同一测试用例 ID 在连续 3 轮集成测试中均标记为 **失败** 时自动触发。

## 失败计数追踪

| 规则 | 说明 |
|------|------|
| 计数粒度 | 按测试用例 ID 独立追踪 |
| 记录位置 | 每轮测试轮次报告中记录各用例连续失败次数 |
| 跨轮保留 | 计数器跨测试轮次保留，不受其他用例通过/失败影响 |

## 失败计数重置

| 条件 | 说明 |
|------|------|
| 用例通过 | 该用例 ID 在某轮测试中通过 |
| 契约修订 | detailed-design.md 中相关接口契约被修订 |
| 用户手动重置 | 用户判断为误报或其他原因手动重置 |

## 证据收集

架构评估启动后自动收集：
- 3 轮失败用例的完整详情（预期 vs 实际、错误日志、堆栈追踪）
- 关联的接口契约定义（从 detailed-design.md 中提取）
- 受影响的子变更列表及其依赖关系
- 已尝试的修复方案及每次修复的结果

## 多方案输出

| 方案 | 内容 | 输出 |
|------|------|------|
| 方案 A（推荐方案） | 完整改造方案 + 改动量估算 + 风险评估 | 改动涉及的设计域、受影响子变更、预期工作量、建议实施顺序 |
| 方案 B（最小改动方案） | 局部修复方案 + 局限性说明 + 风险 | 最小改动范围、不改动范围、长期维护影响 |

## 用户决策

- 使用 AskUserQuestion 展示方案选项（方案 A / 方案 B / 自定义 / 拒绝改造）
- 用户确认后执行选定方案
- 用户拒绝时记录决策，按用户提供的替代方向继续
- 用户判断为误报时重置计数器，返回正常修复循环

# 服务管理约束

集成测试阶段由变更级 agent 独占服务管理，子变更 agent 为纯消费者：

- 变更级 agent 在每轮集成测试开始前执行编译重启
- 子变更 agent 仅通过已知端口使用服务，不执行启停操作
- 服务不可用时上报变更级 agent，走崩溃恢复流程

---

# 崩溃恢复

当集成测试过程中服务崩溃时：

```
集成测试崩溃恢复流程:

1. DETECT    → 变更级 agent 检测到服务端口无响应
2. CLEANUP   → 执行 playwright-cli kill-all（前后端项目）
3. RESTART   → 变更级 agent 执行完整编译重启流程
              (停止→编译后端→编译前端→迁移→启动后端→启动前端→健康检查)
4. RESUME    → 健康检查通过后从断点处继续集成测试
```

# 重复制（执行类阶段）

集成测试阶段属于执行类阶段，采用**收敛驱动**的重复模式，**轮次下限恒为 1 轮（无例外）、轮数由收敛实际发生在第几轮决定**（参见 `skills/kflow-integration-test/references/repetition.md` §14）：

- **档位来源**：读取变更级 `.status.md` 基本信息的「变更档位」字段（缺失按 `完整` 档处理）。变更档位 SHALL 只决定**每轮审查形态与产出深度**，SHALL NOT 决定轮数。
- **轮数**：SHALL NOT 预置或受限于任何数值；达成见证轮即终止，无须凑轮数。
- **终止条件（唯一成功终止条件）**：某轮同时满足见证轮四项判据——(a) 零新发现、(b) 零修改、(c) 报告证明全部集成场景已完成全量遍历、(d) 累积未复核修复清单内全部条目逐项复核通过——时 SHALL 终止，终止结果 `收敛`。
- **不收敛终止**：命中不收敛判定（无进展 / 振荡 / 安全丝）时 SHALL 终止，终止结果 `未收敛`，进入非收敛分支（skill-suggestion.md + AskUserQuestion + 可标记 ⚠️ 阻塞）。
- **审查范围冻结**：主 Agent 每轮从阶段产物既有内容生成审查对象集合并冻结，审查维度限于本阶段枚举；冻结范围之外的发现降级为「范围外观察」——不改产物、不计入本轮新发现数、不阻断收敛；引入范围外新内容的轮次 SHALL NOT 判为见证轮。
- **回退重执行**：SHALL NOT 预置或提高轮数；「最近修订信息」的受影响项清单仅供验证门控的「受影响项 100% 覆盖」使用。

> **权威定义**：终止模型、见证轮判据、不收敛判定与审查范围冻结唯一定义于 `convergence-driven-repetition` 能力，本 Skill 仅引用，SHALL NOT 自行定义轮次数值或终止条件。

## 每轮工作内容

**遍历项**：integration-tests/ 全部集成场景

**每轮流程**：
1. 遍历全部集成场景，逐条多服务协作验证：
   - 前后端：浏览器或 API 调用
   - 纯后端：API 调用
2. 已通过的场景仍需重跑验证无回归
3. 失败的场景按四分法根因分类处理：
   - 接口实现错误 → 定位子变更 → 修复代码
   - 接口契约错误 → 更新契约 → 联动修复
   - 测试用例错误 → 修正测试用例
   - 架构设计错误 → 架构评估自动触发（连续3轮同用例失败）
4. 失败计数按测试用例 ID 独立追踪

**每轮产物**：round-{n}.md 轮次报告

**轮次结束后**：更新 .status.md 执行轮次计数器

## 复杂度评估

复杂度评估仅信息展示，不驱动执行行为：

```
复杂度分 = 集成场景数 × 2 + 子变更数 × 1.5

低复杂度 (< 20 分) / 中复杂度 (20-50 分) / 高复杂度 (> 50 分)
```

分级阈值保留但仅用于信息分类，复杂度分写入 .status.md 备注列标注「仅供参考，不驱动执行行为」。复杂度不参与轮次决策——轮数由收敛实际发生在第几轮决定；迭代终止由见证轮收敛或命中不收敛判定决定。

## 执行流程

```
1. 复杂度评估 → 写入 .status.md 备注列（仅信息展示，不驱动执行行为）

1.5 INIT → 主 Agent 写入 .status.md 执行轮次为 1 轮（无轮数上限；参见 references/repetition.md §14）
    └── 判定流程: 不推算轮数——轮数由收敛决定；读取变更级 .status.md「变更档位」字段仅用于确定每轮审查形态与产出深度；回退重执行时读取「最近修订信息」的受影响项清单供验证门控使用，SHALL NOT 用于推轮次

2. 构建阶段专属提示词
   ├── 分层加载（基础层 + 执行层 + 服务层）:
   │   ├── skills/kflow-integration-test/references/state-values.md（摘要）
   │   ├── skills/kflow-integration-test/references/gates.md（当前阶段相关门控）
   │   ├── skills/kflow-integration-test/references/repetition.md
   │   ├── skills/kflow-integration-test/references/service-lifecycle.md
   │   └── skills/kflow-integration-test/references/hooks.md（服务相关章节）
   ├── 输入: integration-tests/ + detailed-design.md + service-guide.md
   ├── 执行要求: 集成测试执行 + 四分法修复循环
   ├── traceability.md 待填充列: 集成测试(ID)
   ├── 覆盖率目标: 100%
   ├── 重复制遍历指令: 「每轮遍历全部集成场景逐条独立执行。更新 .status.md 中执行轮次计数器为当前轮次号。禁止按轮次分段分配工作重点——每轮均须运行全部集成场景。审查对象集合已冻结，SHALL NOT 审查清单之外的文件或内容、SHALL NOT 新增审查维度、SHALL NOT 借审查之名新增功能点/字段/章节/分支。当某轮零新发现且零修改、且报告证明全部集成场景已完成全量遍历、且累积未复核修复清单内全部条目逐项复核通过时，该轮构成见证轮，SHALL 提前返回验收报告。达成收敛或命中不收敛判定之前 SHALL NOT 无理由返回，SHALL NOT 预设轮数上限。冻结范围之外发现的问题 SHALL 记为『范围外观察』，不在本轮修复、不计入本轮新发现数。」
   ├── 轮间摘要注入（第 2 轮起）: 主 Agent 每轮子代理返回后提取摘要（已发现问题/未解决问题/覆盖率变化/累积未复核修复清单/范围外观察/本轮建议关注），注入下一轮子代理 prompt（参见 repetition.md §13）；见证轮候选须逐项复核「累积未复核修复清单」内全部条目
   └── 完成承诺: COMPLETED

3. 启动 Agent 迭代子代理 (Agent(description, prompt, run_in_background))
   └── 子代理内维持现有四分法修复循环 + 架构评估自动触发

4. 主 Agent 验收
   ├── 轮次: .status.md 执行轮次 >= 1 且最近一轮为见证轮（终止结果 `收敛`）
   ├── 审查范围: 最近一轮未引入冻结审查对象集合之外的新内容；越界 → 拒收该轮并要求在冻结范围内重审
   ├── 产物: round-{n}.md + summary.md 存在且格式正确
   ├── 覆盖率: traceability.md「集成测试」列覆盖率 = 100%
   ├── summary.md 标记「集成测试通过」
   └── 无占位符: 无 TODO/TBD/{待填写}
```

## 验收结果处理

- **通过** → 更新 .status.md + 填写 traceability.md 对应列 → 释放审计阶段门控
- **无见证轮且未命中不收敛判定** → 拒收，直接重新启动 Agent 子代理继续迭代，不进入 AskUserQuestion
- **引入范围外新内容（越界轮）** → 拒收该轮，要求子代理在冻结范围内重新审查，不进入 AskUserQuestion
- **命中不收敛判定；或产物不合格** → 进入非收敛分支：记录 skill-suggestion.md → AskUserQuestion 询问重跑；用户选「否」→ 标记 ⚠️ 阻塞

> **终止结果**：阶段终止时 SHALL 在 .status.md 写入终止结果，取值 `收敛` / `未收敛`；`执行轮次` 字段格式为 `{N} 轮`（无分母）；具体缘由（无进展 / 振荡 / 安全丝）写入 `docs/skill-suggestion.md`。

# 核心提醒

- 入口先做阶段适用性四态判定（仅轻量档）：声明 `⏭️ 不适用` 且有判定依据时 SHALL NOT 启动本 Skill，直接进入审计阶段，归档门控视为满足
- 无声明依据的 `⏭️` 一律阻塞；判定依据不可读时按 `✅ 适用` 保守回退
- 内聚四分法修复循环，不委托给 kflow-bug-fix
- 接口契约错误需联动评估受影响子变更，更新 detailed-design.md
- 架构评估连续 3 轮同用例失败自动触发
- 失败计数按测试用例 ID 独立追踪，跨轮保留
- 架构设计错误触发阶段回退（设计阶段 ⚠️ 需修订）
- 所有测试通过后才允许进入审计和归档
- traceability.md「集成测试」列覆盖率目标 100%
- 轮次下限恒为 1 轮、轮数由收敛实际发生在第几轮决定（SHALL NOT 预置或受限于任何数值）；达成见证轮（零新发现 + 零修改 + 报告证明全部集成场景已完成全量遍历 + 累积未复核修复清单内全部条目逐项复核通过）即返回验收报告，终止结果 `收敛`；命中不收敛判定时终止结果 `未收敛` 并升级用户，SHALL NOT 为凑满上限而空转

- 无见证轮且未命中不收敛判定时拒收并直接重新启动 Agent 子代理；命中不收敛判定（无进展 / 振荡 / 安全丝）时进入非收敛分支并升级用户
