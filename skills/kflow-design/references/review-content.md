# 设计审查内容

设计审查按**变更档位**分级执行（档位读取自变更级 `.status.md` 的「变更档位」字段，缺失按 `完整` 档处理），四视角检查清单在三档下的覆盖方式不同：

| 变更档位 | 审查模式 | 检查清单覆盖方式 | 产物 |
|---------|---------|----------------|------|
| 轻量 | 简化模式 | 单 Agent 串行覆盖业务/技术/安全/质量四视角全部检查项 | 单一 `synthesis.md` |
| 标准 | 两视角模式 | 两个 Agent 并行：业务+技术视角、安全+质量视角；各自覆盖对应两视角的全部检查项 | `business-technical-review.md` + `security-quality-review.md` + `synthesis.md` |
| 完整 | 完整模式 | 四个 Agent 并行，各负责一个视角 | 四份视角报告 + `synthesis.md` |

> **检查项不得缩减**：轻量档单 Agent 与标准档两视角 SHALL 覆盖完整档四视角的全部检查项，仅并行度与产物形态随档位变化。

## 完整模式（四 Agent 并行调度）

使用 Agent 工具并行启动四个审查 Agent（变更级一次执行）：

```
并行调度:
  Agent(Business Agent)  → 业务视角审查
  Agent(Technical Agent) → 技术视角审查
  Agent(Security Agent)  → 安全视角审查
  Agent(Quality Agent)   → 质量视角审查

审查批次目录: cross-reviews/{YYYYMMDD}-{HHMMSS}/
```

## 标准模式（两 Agent 分组并行调度）

使用 Agent 工具并行启动两个审查 Agent（变更级一次执行）：

```
并行调度:
  Agent(Business+Technical Agent) → 覆盖业务视角与技术视角的全部检查项
  Agent(Security+Quality Agent)   → 覆盖安全视角与质量视角的全部检查项

审查批次目录: cross-reviews/{YYYYMMDD}-{HHMMSS}/
产物: business-technical-review.md + security-quality-review.md + synthesis.md
```

## 简化模式（单 Agent 串行）

简化模式下由单 Agent 串行覆盖以下全部四视角检查项，单轮输出单一综合报告（synthesis.md），不执行分级重审闭环。

## 业务视角

| 检查项 | 说明 |
|--------|------|
| 功能完整性 | 所有功能点是否有对应实现设计 |
| 业务流程正确性 | 业务流程是否符合业务规则 |
| 边界条件覆盖 | 边界条件和异常场景是否考虑 |
| 用户故事覆盖 | 设计是否完整覆盖用户故事 |

## 技术视角

| 检查项 | 说明 |
|--------|------|
| 数据模型合理性 | 数据模型是否符合业务需求 |
| 接口设计规范性 | 接口是否遵循项目规范 |
| 技术选型合理性 | 技术方案是否合适 |
| 模块划分合理性 | 模块划分是否清晰 |
| 术语一致性 | 设计文档实体名称是否对齐 CONTEXT.md 领域词汇表 |
| NFR 设计完整性 | 性能/安全/可用性/可维护性是否覆盖 |

## 安全视角

| 检查项 | 说明 |
|--------|------|
| 权限控制 | 接口是否有适当的权限校验 |
| 数据保护 | 敏感数据是否有保护措施 |
| 安全风险 | 是否存在 SQL注入、XSS 等风险 |
| 认证授权 | 认证授权机制是否完善 |

## 质量视角

| 检查项 | 说明 |
|--------|------|
| 性能考量 | 是否考虑性能优化 |
| 可扩展性 | 设计是否便于扩展 |
| 可维护性 | 代码结构是否清晰 |
| 测试覆盖 | 测试用例是否完整 |
