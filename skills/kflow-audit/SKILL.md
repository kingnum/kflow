# 角色

变更级使用评估审计师。按变更档位执行两条审计路径之一（轻量档 → 主 Agent 轻量自检；标准档与完整档 → 七维度加权评估），作为归档门控和随时手动调用工具。审计未通过时按问题归属阶段触发回退路由。

# 任务

确定审计范围 → 收集审计材料 → 按变更档位分流（轻量档 → 轻量自检；标准/完整档 → 七维度并行评估（含 Post-mortem 汇总）→ 计算评分）→ 问题分级（阻塞/严重/建议）→ 审计回退路由 → 输出对应形态的审计产物 → 审计通过或触发回退。

# 门控检查

审计触发方式：
- **归档前自动触发**：集成测试通过后进入归档流程时，自动执行审计作为归档门控
- **手动调用**：用户直接调用 kflow-audit，对指定变更或全部活跃变更执行审计

归档门控规则：
- 阻塞级问题（缺少必须产物、阶段跳转、审查未闭环）→ 阻断归档
- 严重级问题（测试覆盖率不足、审查问题未全部关闭）→ 阻断归档
- 建议级问题（文档格式不规范、测试轮次超出该变更档位基线）→ 不阻断归档，记录改进建议
- **轻量档轻量自检**：阻塞级问题（缺少必须产物、越界跳阶段、裁剪无声明依据）→ 阻断归档；轻量自检 SHALL 保留归档门控地位，不因降级而丧失门控能力
- **裁剪豁免**：有阶段适用性声明依据的裁剪不判缺项，SHALL NOT 因合法裁剪的产物缺失阻断归档

# 审计路径分流

审计 SHALL 读取变更级 `.status.md` 的「变更档位」字段并据此分流（字段缺失时按 `完整` 档处理）：

| 变更档位 | 审计路径 | 执行者 | 产物形态 |
|---------|---------|--------|---------|
| `轻量` | 轻量自检 | 主 Agent（SHALL NOT 启动子代理） | 简化审计记录（检查项结论 + 问题清单） |
| `标准` / `完整` | 七维度加权评分 | 七维度并行评估子代理（4 个 Agent） | 审计报告（七维度评分表 + 加权总分 + 问题清单 + 改进建议 + 效率统计） |

- `标准` 与 `完整` 档 SHALL 按下方「审计维度（七维度评估体系）」执行，SHALL NOT 降级为轻量自检。
- `轻量` 档 SHALL 走下方「轻量档轻量自检路径」，SHALL NOT 启动七维度评估子代理。

## 轻量档轻量自检路径

`变更档位 = 轻量` 时，审计 SHALL 由七维度加权评分子代理审计**降为主 Agent 轻量自检**：SHALL NOT 启动七维度评估子代理，SHALL NOT 计算加权总评分，SHALL NOT 输出七维度评分表。主 Agent 直接执行下列三项检查项。

### 三项检查项

| 序号 | 检查项 | 检查内容 | 阻塞级判定 |
|------|--------|---------|-----------|
| 1 | 阶段完整性 | 无越界的阶段跳转（阶段顺序是否被遵守、是否存在跳阶段） | 存在越界跳阶段 |
| 2 | 阶段产物存在性与无占位符 | 必须产物是否存在、内容是否非空、是否无占位符 | 缺少必须产物或存在占位符 |
| 3 | 裁剪合法性 | 每个 `⏭️ 不适用` 阶段均有变更级 `.status.md` 阶段适用性声明依据 | 存在无声明依据的 `⏭️` |

**裁剪豁免**：合法裁剪 SHALL NOT 判为缺项——`api-tests/`、`e2e-tests/`、`test-reports/integration/` 缺失且该阶段有阶段适用性声明依据时，SHALL NOT 判定为缺项或扣分；有声明依据的 `⏭️ 不适用` 阶段 SHALL NOT 判为跳阶段。无声明依据的 `⏭️` 则判为阻塞级问题。 按项目类型产生的 `⏭️ 跳过`（纯后端项目的 E2E测试阶段与 E2E测试列）不按本项判定。

### 简化审计记录形态

轻量自检 SHALL 输出简化审计记录，含「检查项结论」与「发现的问题清单」两部分；SHALL NOT 含七维度评分表与加权总分（格式见「简化审计记录格式（轻量档）」）。

### 归档门控地位

轻量自检 SHALL 保留归档门控地位，不因降级而丧失门控能力：

- 发现阻塞级问题（缺少必须产物、越界跳阶段、裁剪无声明依据）→ 判定为**不通过**，SHALL 阻断归档并触发审计回退路由
- 无阻塞级问题 → 判定为**通过**，允许进入 `kflow-archive`
- 问题分级沿用阻塞 / 严重 / 建议三级；严重级与建议级问题 SHALL 记录到简化审计记录的问题清单，建议级问题同时记录到 `docs/skill-suggestion.md`

# 审计维度（七维度评估体系）

> **适用档位**：本节 SHALL 仅用于 `标准` 与 `完整` 档；`轻量` 档 SHALL NOT 走本节，改为主 Agent 轻量自检（见「轻量档轻量自检路径」）。

| 维度 | 权重 | 检查项 | 评分标准 |
|------|------|--------|---------|
| 流程合规性 | 22% | 阶段顺序遵守、跳阶段检查、可选阶段处理、回退流程规范性 | 0-100 |
| 产物完整性 | 23% | 必须产物存在性、条件产物处理、产物内容质量（非空、无占位符） | 0-100 |
| 审查质量 | 20% | 设计审查与代码审查按变更档位要求的形态执行（见下方按档位给分规则）、审查问题闭环（追踪矩阵全部关闭） | 0-100 |
| 测试充分性 | 15% | 接口单元测试通过率（该阶段适用时）、E2E 测试通过率（该阶段适用时）、集成测试执行（该阶段适用时）、多轮测试记录 | 0-100 |
| 缺陷管理 | 10% | 根因分类执行、修复闭环、设计错误回退触发正确性 | 0-100 |
| 效率指标 | 5% | 各阶段耗时、测试轮次（以变更档位基线为达标基准：轻量 1 / 标准 3 / 完整 10）、缺陷发现-修复周期 | 0-100 |
| Post-mortem 汇总 | 5% | 读取所有子变更 fix-report 的关联建议，汇总架构改进机会 | 0-100 |

**总评分 = Σ(维度得分 × 权重)**，满分 100 分。

**各维度按变更档位给分与不误扣规则**：

档位来源：变更级 `.status.md` 基本信息的「变更档位」字段（`轻量` / `标准` / `完整`），字段缺失时按 `完整` 档处理。各维度判定 SHALL 以该档位为基准，SHALL NOT 因轻量档按设计裁剪的流程要求而判缺项或扣分。

| 维度 | 按档位给分依据 | 不误扣声明（SHALL NOT） |
|------|--------------|----------------------|
| 流程合规性 | 按该档位对应的阶段与轮次要求判定阶段顺序、跳阶段、可选阶段处理、回退规范性 | 将 `轻量` 档的零轮自审判定为跳阶段或流程违规 |
| 产物完整性 | 必须产物存在性 + 条件产物处理（🔶 / ⏭️ 图例）+ 内容质量（非空、无占位符） | 将 `轻量` 档缺失的 `self-reviews/` 目录判定为缺项 |
| 审查质量 | 按档位要求的审查形态检查：设计审查 完整档四视角 / 标准档两视角 / 轻量档单 Agent 综合；代码审查 标准档与完整档两视角 / 轻量档单 Agent；审查问题闭环（追踪矩阵全部关闭） | 因缺少超出该档位要求的视角报告而判为缺项或扣分；因单 Agent 审查形态而判为缺项 |
| 测试充分性 | 仅检查该阶段**适用**的测试环节（接口单元测试、E2E 测试、集成测试按阶段适用性声明逐项判定，`⏭️ 不适用` 的阶段不参与判定） | 将合法裁剪（有阶段适用性声明依据）而缺失的 `api-tests/`、`e2e-tests/`、`test-reports/integration/` 判定为缺项或扣分；将合法裁剪的测试阶段判定为未执行 |
| 效率指标 | 测试轮次以档位基线为达标基准：`轻量` 1 轮 / `标准` 3 轮 / `完整` 10 轮 | 以固定轮次阈值判定 `轻量` 档或 `标准` 档轮次偏多（仅当轮次超过该变更档位基线时记为偏差） |

# Post-mortem 汇总评估

审计时 SHALL 读取所有子变更的 fix-report 文件，汇总架构改进建议。

## 汇总流程

```
1. 扫描所有子变更 fix-report 目录
   └── subchanges/*/test-reports/fix-reports/*.md

2. 提取每个 fix-report 的"关联建议"字段
   └── 架构改进建议、测试 seam 缺失报告

3. 按类型归类：
   ├── 测试 seam 缺失 → 测试架构改进机会
   ├── 模块耦合 → 模块化改进机会
   ├── 接口契约 → 契约设计改进机会
   └── 其他 → 通用改进建议

4. 汇总到审计报告的改进建议章节
```

## 评分标准

| 评分 | 条件 |
|------|------|
| 100 | 所有 fix-report 已完成 post-mortem，架构建议已汇总 |
| 70 | 大部分 fix-report 已完成 post-mortem，少数未完成 |
| 40 | 部分 fix-report 缺失关联建议字段 |
| 0 | 无 fix-report 或均未完成 post-mortem |

## 评估内容

| 检查项 | 说明 |
|--------|------|
| Post-mortem 完成率 | 所有子变更 fix-report 是否包含 post-mortem 章节 |
| 架构改进识别 | 是否有被打捞出的架构级改进机会 |
| 建议质量 | 建议是否具体可执行（非"改进代码质量"等空泛建议） |
| 建议传递 | 汇总后的架构改进机会是否可传递给下一变更的设计阶段 |

# 审计回退路由

审计发现问题是第 4 种回退触发来源（与缺陷修复、代码审查、用户需求变更并列）：

```
审计回退流程:

1. 确定问题归属阶段:
   ├── 设计探索/详细设计问题 → 对应设计阶段 ⚠️ 需修订
   ├── 编码问题 → 编码阶段 ⚠️ 需修订
   └── 测试问题 → 对应测试阶段 ⚠️ 需修订

2. 重置后续阶段:
   - 目标阶段之后的所有阶段状态 → ⏳ 待开始
   - 受影响产物标记为"待修订"

3. 联动评估:
   ├── 仅当前变更受影响 → 单独回退
   ├── 接口契约变更 → 依赖该接口的子变更联动回退
   ├── 架构级变更 → 所有子变更联动回退
   └── 审计发现 → 按审计问题归属阶段确定回退范围和联动子变更

4. 修复后重新审计:
   - 修复完成 → 目标阶段 ⚠️ 需修订 → ✅ 完成
   - 后续阶段逐个重新执行
   - 重新进入归档流程时再次触发审计
```

# 核心提醒

- 审计是归档门控，未通过不能归档
- 审计路径按变更档位分流（读取变更级 `.status.md` 的「变更档位」字段，缺失按 `完整` 档）：`轻量` 档 → 主 Agent 轻量自检（三项检查项，不启动子代理、不算加权总分、不输出七维度评分表），输出简化审计记录；`标准`/`完整` 档 → 七维度加权评分，输出审计报告。`标准`/`完整` 档 SHALL NOT 降级为轻量自检
- 轻量自检 SHALL 保留归档门控地位：缺少必须产物、越界跳阶段、裁剪无声明依据 → 不通过并阻断归档
- 各维度 SHALL 以变更档位为判定基准（读取变更级 `.status.md` 的「变更档位」字段，缺失按 `完整` 档）：轻量档零轮自审不判流程违规、缺失 `self-reviews/` 目录不判缺项、单 Agent 审查不判缺项，测试轮次以档位基线（轻量 1 / 标准 3 / 完整 10）为达标基准
- 合法裁剪不判缺项：`api-tests/`、`e2e-tests/`、`test-reports/integration/` 缺失且有阶段适用性声明依据时，SHALL NOT 判定为缺项或扣分；无声明依据的 `⏭️` 判为阻塞级问题
- 「测试充分性」维度按「该阶段适用时」检查——`⏭️ 不适用` 的测试阶段不参与判定
- 阻塞/严重级问题阻断归档，建议级不阻断
- 阻塞级：缺少必须产物、阶段跳转、审查未闭环
- 严重级：测试覆盖率不足、审查问题未全部关闭
- 建议级：文档格式不规范、测试轮次超出该变更档位基线
- 审计回退按问题归属阶段确定回退范围和联动子变更
- Post-mortem 汇总需扫描所有子变更 fix-report 的关联建议，打捞架构级改进机会
- 支持指定变更或全部活跃变更审计
