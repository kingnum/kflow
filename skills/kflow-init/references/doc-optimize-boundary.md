# 存量文档优化工具的适用边界例外

> **加载层级**: 基础层
> **适用阶段**: kflow-init 的 INJECT 步骤（变更流程强制规则注入）

## 1. 背景

部分消费方项目会在 `CLAUDE.md` 的「项目自定义规则」区块中自维护一条适用边界，例如：

> 「KFlow Skills 仅在本项目的功能变更与缺陷修复场景调用，其余工作（含规则/文档维护）一律不调用。」

该规则会把项目级文档维护工具一并挡在门外。`kflow-doc-optimize` 是**项目级文档维护工具**，不属于变更流程的任何阶段，若被该边界排除，存量文档将无法通过该工具优化。

## 2. 例外声明

`kflow-init` 注入的「变更流程强制规则」中 SHALL 声明：

- `kflow-doc-optimize` 作为独立维护工具，可用于优化存量文档的修订记录与体积，不属于变更流程
- 该工具**不受变更流程适用边界约束**——即使项目声明了「KFlow Skills 仅在功能变更与缺陷修复场景调用」，文档维护场景下仍可正常调用

注入模板中的对应条目：

```markdown
8. **存量文档优化**: `kflow-doc-optimize` 作为独立维护工具，可用于优化存量文档的修订记录与体积
   （文档优化 / 文档瘦身 / 拆分文档 / 清理修订记录），不属于变更流程的任何阶段；
   **不受本项目变更流程适用边界（如「KFlow Skills 仅在功能变更与缺陷修复场景调用」）的约束**，
   在文档维护场景下可正常调用。项目在其自维护的规则区块中声明该边界时，SHALL 一并记入此例外
```

## 3. 项目自定义规则区块的保护

例外声明的落地分两处，二者的维护方不同：

| 位置 | 维护方 | kflow-init 的行为 |
|------|--------|------------------|
| 「变更流程强制规则」区块 | kflow-init | 按模板版本幂等注入/更新，含上述例外声明 |
| 「项目自定义规则」区块 | 项目自身 | **不读取、不替换、不删除**其内容 |

因此，项目若在其自维护的规则区块中写有适用边界，须由项目侧**手工**补入例外声明。`kflow-init` 的注入内容已提供便于同步的表述，但 SHALL NOT 改写该区块。

## 4. 与存量优化的衔接

- `kflow-init` 负责项目级配置（`autoCompactWindow`、主 Agent 门控 hook）与例外声明注入
- `kflow-doc-optimize` 负责存量文档的扫描、清单、确认、执行与引用校验
- 归档的设计合并步骤（`kflow-archive`）负责新变更产生文档的自动留存边界

三者分工见 `docs/designs/skills/kflow-doc-optimize.md`「三层分工」。
