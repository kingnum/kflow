# VERIFY 规则 — 引用扫描、更新与校验

> **加载层级**: 基础层
> **适用阶段**: kflow-doc-optimize 的 VERIFY 步骤

## 1. 引用来源

扫描下列位置中对被优化文档的引用：

| 来源 | 形式 |
|------|------|
| 项目文档 | Markdown 链接 `[..](path)`、行内路径 `` `path` ``、正文中的文件路径 |
| Skill 规则文件 | `.claude/skills/**/SKILL.md`、`.claude/skills/**/references/**` 中的路径 |
| 脚本 | `scripts/**` 中的路径字符串 |
| 项目配置 | `CLAUDE.md`、`docs/**` 中的路径 |

## 2. 更新规则

| 被优化文档的变化 | 引用更新 |
|-----------------|---------|
| 单文件拆分为目录化结构 | 原路径 `foo.md` → `foo/index.md`（引用整体文档）或 `foo/<section>.md`（引用特定章节） |
| 建立章节索引 | 路径不变；可在引用处补充章节锚点 |
| 修订记录裁剪 | 路径不变；无需更新引用 |

- 引用更新 SHALL 在 EXECUTE 的同一步内完成，SHALL NOT 留待后续
- 无法判断引用目标应指向 `index.md` 还是某个分册时，SHALL 报告该引用并交由用户裁决，其余引用先行更新

## 3. 校验

### 3.1 校验步骤

```
1. 逐条读取受影响引用清单
2. 对每条引用：
   ├── 解析其目标路径（相对项目根或文档所在目录）
   ├── 检查目标文件是否存在
   └── 存在 → 通过；不存在 → 记录为断链
3. 断链数 = 0 → 通过
   断链数 > 0 → 报告断链清单并停止，SHALL NOT 静默通过
```

### 3.2 校验范围

- 全部受影响引用（执行前留档的清单）
- 被优化文档自身内部的分册交叉引用
- 拆分后 `index.md` 中指向各分册的链接

## 4. 优化报告

校验通过后输出 `docs/doc-optimize-report.md`，内容包含：

| 小节 | 内容 |
|------|------|
| 扫描范围 | 扫描的目录与文件数 |
| 实际执行项 | 逐项列出执行的优化动作与对应文档 |
| 体积变化 | 每项优化前后的体积对比（表格） |
| 更新过的引用 | 逐条列出更新前后的路径 |
| 引用校验结论 | 受影响引用总数、通过数、断链数（应为 0） |
| 未执行项 | 用户选择不执行或存在歧义而交由裁决的项，及原因 |

## 5. 停止条件

以下情况 SHALL 报告并停止，不得继续执行或自行绕过：

- 存在无法解析的引用（断链）
- 拆分后的分册无法从原文确定章节边界
- 引用更新存在歧义且用户尚未裁决
- 执行前留档清单缺失（未产出 `docs/doc-optimize-references.md`）
