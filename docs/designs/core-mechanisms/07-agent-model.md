## 十五、子代理执行模型

> **版本**: 1.8.0 新增

> 完整规范参见 `各执行类 skill 的 references/repetition.md`

### 15.1 概述

执行类阶段（计划/编码/代码审查/接口单元测试/E2E测试/集成测试/缺陷修复）统一采用**收敛驱动的重复制**模式：轮数由收敛实际发生在第几轮决定，SHALL NOT 预置或受限于任何轮数，全局下限为 1 轮。子代理每轮遍历全部工作项独立执行完整流程，禁止按轮次分段分配工作重点。

**终止（唯一成功终止条件）**：某轮同时满足见证轮四项判据——(a) 零新发现、(b) 零修复零修改、(c) 报告证明全部工作项与全部审查对象已完成全量遍历、(d) 累积未复核修复清单内全部条目逐项复核通过——时终止，终止结果 `收敛`。

**不收敛终止**：命中不收敛判定（无进展 / 振荡 / 安全丝）时终止，终止结果 `未收敛`，升级用户（记录 `skill-suggestion.md` + AskUserQuestion + 可标记 ⚠️ 阻塞）。

**审查范围冻结**：每轮审查对象集合由主 Agent 从阶段产物既有内容生成并冻结，审查维度限于该阶段固定枚举；子代理 SHALL NOT 扩大审查对象集合、SHALL NOT 新增审查维度。冻结范围之外的发现降级为「范围外观察」——不修改产物、不计入本轮新发现数、不阻断收敛；引入范围外新内容的轮次 SHALL NOT 判为见证轮。跨轮审查对象集合 MAY 因阶段输入变化（如回退重执行新增受影响项）由主 Agent 更新。

**档位语义**：变更档位只决定**每轮审查形态**（轻量单 Agent 串行覆盖全部视角 / 标准两视角并行 / 完整四视角并行）与产出深度，SHALL NOT 决定轮数。变更级 `.status.md` 不含「变更档位」字段时按 `完整` 档确定审查形态与产出深度。

**验证门控**：受影响项 100% 覆盖（回退重执行场景，存在受影响项清单时）+ 产物完整性；两项全部通过方验收通过。

`执行轮次` 字段格式为 `{N} 轮`（无分母，下限 1 轮，无上限）；读取侧遇到历史 `{N} / {上限}` 形式时取分子、忽略分母。

> 完整规范（复杂度公式、轮次执行细节、prompt 规范、审查范围冻结、验证门控）参见 `各执行类 skill 的 references/repetition.md`；权威定义见 `convergence-driven-repetition` 能力

### 15.2 轮间摘要传递

> **版本**: 2.6.0 新增

每轮子代理返回后，主 Agent 从审查报告/产物差异中提取轮间摘要（已发现问题/未解决问题/覆盖率变化/**累积未复核修复清单**/**范围外观察**/本轮建议关注），注入下一轮子代理 prompt，使后期轮次可优化注意力分配（已修复项快速回归/未解决项重点分析/未涉及项全量兜底）。摘要仅优化注意力分配，不跳过任何工作项，全量遍历兜底始终保留。**累积未复核修复清单**由主 Agent 维护，累积自循环开始以来全部尚未通过独立复核的修复；它是见证轮第 (d) 项复核义务的唯一输入，见证轮候选须逐项复核该清单。**范围外观察**字段承载冻结范围之外的发现，使后续轮次不重复发现同一范围外内容。

> 完整规范参见 `各执行类 skill 的 references/repetition.md` §13

### 15.3 子代理隔离规则强化

> **版本**: 2.7.0 新增（变更 enforce-subagent-execution），2.8.0 新增后台权限失败回退（变更 portable-permission-propagation）

§12 强化内容：
- **主 Agent 职责边界硬线**：执行类阶段主 Agent 职责 = 调度 + 验收，SHALL NOT 直接执行阶段主工作（编码/修复/测试/审查/计划等），无例外
- **轮次级重试**：某轮子代理崩溃 → 新建 Agent 重跑该轮（≤3 次重试），全部失败标记 ⚠️ 阻塞
- **后台权限失败回退前台子代理**：后台子代理因权限问题失败时，主 Agent SHALL 创建新的前台子代理（run_in_background=false）重新执行，SHALL NOT 直接接管，回退不计入轮次级重试 3 次上限
- **权限预配置**：由 kflow-init 根据 `kflow-init 的 references/permission-model.md` 自动配置，取代手动预配置
- **双写强制**：集中定义在 `各执行类 skill 的 references/repetition.md` §12，各执行类阶段 SKILL.md 内联规则框

> 完整规范参见 `各执行类 skill 的 references/repetition.md` §12

## 十六、自审机制

> **版本**: 1.10.0 新增

> 完整规范参见 `各设计类 skill 的 references/self-review.md`

### 16.1 概述

kflow-explore、kflow-prototype-design、kflow-design、kflow-plan 四个阶段在产物初稿完成后执行自循环审查（self-review），**轮数不设上限**——由收敛实际发生在第几轮决定，全局下限为 1 轮（无例外；SHALL NOT 存在 0 轮豁免路径）。变更档位只决定**每轮审查形态与产出深度**，SHALL NOT 决定轮数。

每轮由独立子代理串行执行全维度检查，按阶段类型采用不同维度组合（explore: 完整性/闭环性/必要性/清晰性；prototype: 覆盖性/一致性/可用性/完整性；design: 一致性/完备性/可行性/可测性；plan: 计划阶段 4 个定制维度）。审查对象集合由主 Agent 每轮从阶段产物既有内容生成并冻结，审查维度集合封闭。

**轮间摘要注入**：第 2 轮起，每轮子代理 prompt SHALL 注入前轮摘要（格式见各设计类 skill 的 `references/self-review.md` §11；执行类见 `references/repetition.md` §13），使前轮修复与遗留问题进入本轮视野；见证轮候选须逐项复核摘要「累积未复核修复清单」中的全部条目。

**见证轮（唯一成功终止条件）**：某轮同时满足四项判据——(a) 零新发现、(b) 零修复零修改、(c) 报告证明全部 4 个审查维度与全部审查对象已完成全量遍历、(d) 累积未复核修复清单内全部条目逐项复核通过——时构成见证轮，自审终止并写入终止结果 `收敛`。第 (d) 项的复核义务原先由独立的追加轮次承担，现上提为见证轮判据本身（清单非空且存在未通过复核的条目时该轮 SHALL NOT 被判定为见证轮）。

**不收敛终止**：命中不收敛判定（无进展 / 振荡 / 安全丝）时终止，写入终止结果 `未收敛`，升级用户。原型阶段 VERIFY 的 nav-check / playwright-check / ux-check 三条流程同构适用（同样不预设轮数上限，报告命名为 `round-{N}.md`，N 为收敛实际轮次）。机制权威定义见 `convergence-driven-repetition` 能力。

**评分底线仅完整档适用**：完整档每轮输出各维度评分（0-10 量纲），各维度评分均 > 8 **且**该轮构成见证轮方为收敛。**评分 ≤ 8 时该轮 SHALL 列出对应的具体问题项**，使「评分 ≤ 8」等价于「存在新发现」，从而自然不构成见证轮——不再需要独立于收敛判据的第二套终止条件。标准档与轻量档不适用评分底线。

**kflow-prototype-design 例外**：该阶段仅在该变更选择「子代理自动审查验证」审查方式时执行自审；选择「人工审查」时完全跳过 SELFREV，不保留兜底轮次，直接进入用户评审 REVIEW 步骤。该跳过属**流程分支**，SHALL NOT 被视为 0 轮豁免。

> **缺省回退**: 变更级 `.status.md` 不含 `变更档位` 字段时按 `完整` 档确定审查形态与产出深度。
>
> **终止结果**: 阶段终止时 SHALL 写入 `终止结果` 字段，取值 `收敛` / `未收敛`。`收敛` 当且仅当该阶段以见证轮终止；`未收敛` 用于不收敛升级路径，且 SHALL 有对应的升级记录（`docs/skill-suggestion.md` 条目 + 用户决策）。具体缘由（无进展 / 振荡 / 安全丝）写入 `docs/skill-suggestion.md`，SHALL NOT 作为终止结果字段的取值。
>
> 轮次取值、审查范围冻结与产物门控规则见 `convergence-driven-repetition` 能力与各设计类 skill 的 references/self-review.md。

## 十七、子代理上下文分层加载

> **版本**: 2.5.0 新增

子代理冷启动时按阶段类型分层加载各 skill 的 `references/` 文件，避免全量加载不相关的上下文。每个核心机制文档和 `references/` 文件头部标注了「加载层级」和「适用阶段」。

### 17.1 分层定义

| 层级 | 加载文件 | 适用阶段 |
|------|---------|---------|
| 基础层 | state-values.md（摘要）、gate-rules.md（当前阶段相关门控） | 全部 |
| 执行层 | repetition-model.md | plan/code/code-review/api-test/e2e-test/integration-test/bug-fix |
| 服务层 | service-lifecycle.md、phase-hooks.md（服务相关章节） | api-test/e2e-test/integration-test |
| 创意层 | self-review.md | explore/prototype-design/design |
| 恢复层 | recovery-protocol.md | 仅恢复场景 |
| 归档层 | archive-rules.md | archive |

### 17.2 各阶段类型加载清单

| 阶段类型 | 加载层级 | 文件清单 |
|---------|---------|---------|
| 纯执行阶段（plan/code/code-review/bug-fix） | 基础层 + 执行层 | state-values.md + gate-rules.md + repetition-model.md |
| 测试阶段（api-test/e2e-test/integration-test） | 基础层 + 执行层 + 服务层 | state-values.md + gate-rules.md + repetition-model.md + service-lifecycle.md + phase-hooks.md |

### 17.3 RELOAD 与分层对齐

子代理执行 RELOAD 步骤时，SHALL 仅重新加载当前已加载层级的文件，不跨层级加载。
