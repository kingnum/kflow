## 二、问题列表

| ID | 标题 | 严重度 | 源头阶段 | 处理路径 | 状态 | 登记时间 | 详情文件 | 关联变更 |
|----|------|--------|---------|---------|------|---------|---------|---------|
| BUG-{NNN} | {标题} | {🔴 阻塞 / 🟡 警告 / 🔵 建议} | {L1/L2/L3/L4} | {缺陷修复快车道 / 功能缺陷变更 / REVISION / —} | {待处理/处理中/已解决/已关闭/已挂起} | {YYYY-MM-DD HH:MM} | [bug-NNN-NNN.md](bug-NNN-NNN.md#bug-nnn) | {变更名 或「—」} |

**列定义**：

| 列 | 取值 | 说明 |
|----|------|------|
| 源头阶段 | `L1` / `L2` / `L3` / `L4` | 四层溯源诊断的问题源头层级 |
| 处理路径 | `缺陷修复快车道` / `功能缺陷变更` / `REVISION` / `—` | L4 且满足快车道条件 → `缺陷修复快车道`（持有 `fix/{BUG-ID}/bugfix-status.md`）；L1/L2/L3 或 L4 不满足快车道条件 → `功能缺陷变更`（关联新建变更）；`REVISION` 表示缺陷关联到既有变更的修订；`—` 表示尚未路由 |
| 状态 | `待处理` / `处理中` / `已解决` / `已关闭` / `已挂起` | 与 `bug-registration` 的缺陷状态流转一致；快车道缺陷在定向验证通过且快速收口校验全部通过后由 `kflow-bug-fix` 更新为 `已解决`，未通过时保持 `处理中` |
| 关联变更 | 变更名 或 `—` | 仅作追溯用途；项目级缺陷不依附于该变更的生命周期，SHALL NOT 因该列存在而要求变更级审计或归档 |

> **阻塞级门控**: 本表中未关闭的 🔴 阻塞级缺陷 SHALL 阻断任意变更的 `kflow-archive` 归档。🟡 警告与 🔵 建议级缺陷 SHALL NOT 阻断归档。
>
> **跨工作区引用**: 引用变更级 `docs/changes/{change}/bugs/` 中的缺陷时 SHALL 使用「工作区路径 + BUG-ID」形式（如 `docs/changes/add-user-auth/bugs#BUG-003`），SHALL NOT 仅使用 BUG-ID。
