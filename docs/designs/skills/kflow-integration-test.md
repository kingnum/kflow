## 门控检查

> **机制说明**：门控规则定义在 [core-mechanisms/03-status-and-tasks.md](../core-mechanisms/03-status-and-tasks.md#34-门控规则)

进入集成测试阶段前检查：
- 阶段适用性声明按四态判定（仅轻量档，见下方「阶段适用性入口门控」）
- 所有子变更编码+审查状态 = ✅ 完成
- 所有子变更接口单元测试状态 = ✅ 完成 或 ⏭️ 不适用（有声明依据）
- 前后端项目：所有子变更 E2E 测试状态 = ✅ 完成 或 ⏭️ 不适用（有声明依据）
- 变更级服务刷新已完成并通过（服务编译、迁移执行、重启、健康检查）
- integration-tests/index.md 文件存在
- 任一不满足则提示先完成前置条件

> **触发条件口径**：前置测试阶段（接口单元测试、E2E 测试）的完成判定为「✅ 完成 **或** 已标记 `⏭️ 不适用`（有声明依据）」——轻量档按阶段适用性声明裁剪掉的测试阶段 SHALL 视为满足前置条件，SHALL NOT 因此阻塞。

## 阶段适用性入口门控

> **机制说明**：阶段裁剪的范围与四态判定矩阵见 [core-mechanisms/04-gates-and-transitions.md](../core-mechanisms/04-gates-and-transitions.md) §5.4；声明字段定义见 `skills/kflow-integration-test/references/state-values.md` §5；钩子豁免见 `skills/kflow-integration-test/references/hooks.md` §1

本机制 SHALL 仅适用于 `变更档位 = 轻量` 的变更；`标准` 档 SHALL NOT 应用。变更档位读取自变更级 `.status.md` 基本信息的「变更档位」字段，字段缺失或读取到历史遗留的 `完整` 取值时按 `标准` 档处理。

### 适用性判定

适用性判定依据为变更级 `detailed-design.md`：

| 判定依据 | 适用性结论 |
|---------|-----------|
| 接口设计章节含本变更新增或修改的接口条目 | ✅ 适用 |
| 「跨子变更接口契约」章节含本变更条目 | ✅ 适用 |
| 上述章节均不含本变更条目 | ⏭️ 不适用 |
| 判定依据产物不存在 / 格式不符 / 字段缺失 | ✅ 适用（保守回退） |

> **保守回退优先于裁剪**：判定依据不可读时 SHALL 按 `✅ 适用` 处理，SHALL NOT 因依据缺失而裁剪阶段。

### 四态判定

| 阶段适用性声明 | test-reports/integration/ | 判定 | 处理 |
|--------------|---------------------------|------|------|
| ⏭️ 不适用 | 不存在 | 合法跳过，通过 | 直接进入审计阶段 |
| ⏭️ 不适用 | 存在 | 不一致，❌ 阻塞 | 提示声明与产物矛盾，要求清理产物或恢复声明 |
| ✅ 适用 | 存在 | 通过 | 正常执行集成测试 |
| ✅ 适用 | 不存在 | ❌ 阻塞 | 输出缺失产物清单 |
| （无声明依据的 ⏭️ 标记） | 任意 | ❌ 阻塞 | 提示缺失裁剪依据 |

### 裁准时行为

声明为 `⏭️ 不适用`、`test-reports/integration/` 不存在且存在判定依据时（仅轻量档）：

- SHALL NOT 启动 `kflow-integration-test`
- SHALL NOT 执行任何 PRE_HOOK / POST_HOOK 步骤（含变更级服务刷新、编译重启、浏览器清理）
- SHALL NOT 产出 `test-reports/integration/summary.md` 与执行报告
- SHALL **直接进入审计阶段**，跳过本阶段执行流程的全部步骤
- 阶段状态由 `kflow-design` 写入适用性声明时一次性标记为 `⏭️ 不适用`，不由本阶段自身更新
- 归档门控 SHALL 视为满足，SHALL NOT 要求集成测试产物存在
- `traceability.md`「集成测试」列 SHALL 整列填 `⏭️`，不计入覆盖率分母

> 轻量档集成测试仍适用时，SHALL 按**单轮全面执行 + 定向重验**口径执行（轮数恒为 1，定向重验后累计），SHALL NOT 按任何档位的轮次数值要求阻塞；不因档位判定为超限或缺项。

## 四分法根因分类

### 分类标准

| 分类 | 占比 | 判定条件 | 处理方式 |
|------|------|---------|---------|
| 接口实现错误 | ~60% | 代码实现不满足接口契约，但契约本身正确 | 定位子变更 → 修复代码 → 子变更重测 → 重新集成 |
| 接口契约错误 | ~20% | 接口契约定义本身有缺陷或不一致 | 更新 detailed-design.md → 评估联动范围 → 修复受影响子变更 → 重新集成 |
| 测试用例错误 | ~15% | 集成测试用例预期与设计不符 | 修正 integration-tests/ → 验证正确性 → 重新集成 |
| 架构设计错误 | ~5% | 架构层面结构性问题 | 标记阻塞 → 触发架构评估 → 用户决策 |

### 修复报告输出路径

| 错误类型 | 报告路径 | 内容要求 |
|---------|---------|---------|
| 接口契约错误 | `test-reports/integration/fix-reports/contract-error-{timestamp}.md` | 契约矛盾点、受影响子变更、修订建议 |
| 架构设计错误 | `test-reports/integration/fix-reports/arch-assessment-{timestamp}.md` | 架构缺陷分析、影响范围、回退建议 |

## 架构评估自动触发

### 触发条件

同一测试用例 ID 在连续 3 轮集成测试中均标记为 **失败** 时自动触发。

### 失败计数追踪

| 规则 | 说明 |
|------|------|
| 计数粒度 | 按测试用例 ID 独立追踪 |
| 记录位置 | 测试执行报告中记录各用例连续失败次数 |
| 跨轮保留 | 计数器跨测试轮次保留，不受其他用例通过/失败影响 |

### 失败计数重置

| 条件 | 说明 |
|------|------|
| 用例通过 | 该用例 ID 在某轮测试中通过 |
| 契约修订 | detailed-design.md 中相关接口契约被修订 |
| 用户手动重置 | 用户判断为误报或其他原因手动重置 |

### 证据收集

架构评估启动后自动收集：
- 3 轮失败用例的完整详情（预期 vs 实际、错误日志、堆栈追踪）
- 关联的接口契约定义（从 detailed-design.md 中提取）
- 受影响的子变更列表及其依赖关系
- 已尝试的修复方案及每次修复的结果

### 多方案输出

| 方案 | 内容 | 输出 |
|------|------|------|
| 方案 A（推荐方案） | 完整改造方案 + 改动量估算 + 风险评估 | 改动涉及的设计域、受影响子变更、预期工作量、建议实施顺序 |
| 方案 B（最小改动方案） | 局部修复方案 + 局限性说明 + 风险 | 最小改动范围、不改动范围、长期维护影响 |

### 用户决策

- 使用 AskUserQuestion 展示方案选项（方案 A / 方案 B / 自定义 / 拒绝改造）
- 用户确认后执行选定方案
- 用户拒绝时记录决策，按用户提供的替代方向继续
- 用户判断为误报时重置计数器，返回正常修复循环

## 服务管理约束

> 完整规范参见 `skills/kflow-integration-test/references/service-lifecycle.md`

## 单轮全面执行 + 定向重验（执行类阶段）

> ⚠ **子代理强制规则**（参见 skills/kflow-integration-test/references/repetition.md §12）：本阶段（集成测试）主工作 MUST 通过 Agent 子代理执行，主 Agent 仅负责调度和验收，SHALL NOT 直接执行集成测试主工作（跨子变更测试/四分法修复/架构评估等），无例外。子代理崩溃时重试（≤3 次），全部失败标记 ⚠️ 阻塞。

集成测试阶段属于执行类**单轮类阶段**，采用**单轮全面执行 + 定向重验**模式：

- **单轮全面执行**：SHALL 在一轮内遍历 integration-tests/ 全部集成场景执行完整流程（逐条多服务协作验证），SHALL NOT 执行第二轮全量审查。单轮执行时 `执行轮次` 记为 1。
- **定向重验**：单轮执行发现失败项时，主 Agent 修复后仅**重跑失败用例**、不重跑全量；属**有界**重试（连续 3 次仍未通过即终止），不构成收敛循环，SHALL NOT 使用任何轮次循环判据。`执行轮次` 随定向重验累计。
- **定向重验 ≠ recheck-round**：`recheck-round` 指旧审查循环到达终止点后追加的复核轮（因依赖已废除的轮数上限而被移除）；定向重验触发于测试失败后的修复动作，二者触发时机、输入、输出均不同，SHALL NOT 混用命名。
- **档位语义**：变更档位只决定**审查形态与产出深度**，SHALL NOT 决定轮数。读取变更级 `.status.md` 基本信息的「变更档位」字段；字段缺失或读取到历史遗留的 `完整` 取值时按 `标准` 档确定审查形态与产出深度。
- **回退重执行**：SHALL NOT 预置或提高轮数；「最近修订信息」的受影响项清单仅供验证门控的「受影响项 100% 覆盖」使用。
- **审查范围冻结**：审查对象集合由主 Agent 从阶段产物既有内容生成并冻结，审查维度限于本阶段固定枚举；冻结范围之外的发现降级为「范围外观察」——不改产物、不计入发现数。
- **字段写入**：`执行轮次` 字段格式为 `{N} 轮`（无分母，下限 1 轮）；阶段终止时 SHALL 在 `.status.md` 写入**终止结果**字段（取值 `执行完成` / `定向重验失败`）。历史遗留的 `收敛` 取值读取侧归并为 `验证通过`，其余归并为 `验证发现问题`。
- **主 Agent 验收判据**：以「执行报告完整（含全量遍历证明）+ 阶段产物齐全 + traceability 覆盖率达标 + 无 TODO/TBD/{待填写} 占位符 + 定向重验全部通过」为通过条件；SHALL NOT 以轮次数量作为通过或拒收依据。

> **权威定义**：执行类阶段的单轮执行与定向重验模型定义于 `agent-iteration-execution` 能力；审查范围冻结定义于 `convergence-driven-repetition` 能力。本 Skill 仅引用，SHALL NOT 自行定义轮次数值或终止条件。

> 通用规范（复杂度公式、prompt 规范、审查范围冻结、验证门控）参见 `skills/kflow-integration-test/references/repetition.md`

### 阶段特定参数

- **遍历项**：integration-tests/ 全部集成场景
- **单轮工作**：逐条多服务协作验证 + 四分法根因分类处理失败 + 架构评估自动触发
- **复杂度权重**：集成场景数 × 2 + 子变更数 × 1.5
- **产物要求**：traceability.md「集成测试」列覆盖率 = 100%，round-{n}.md + summary.md 标记「集成测试通过」

## 阶段衔接

验收通过并更新 `.status.md`（终止结果 `执行完成`）与 traceability.md「集成测试」列之后，SHALL 执行**阶段衔接决策**并直接调度目标阶段 Skill：按 `skills/kflow-integration-test/references/phase-transition.md` 的决策表判定目标阶段状态，按调度映射表定位目标 Skill。系统 SHALL NOT 提示用户输入推进指令（如「继续 {change-name}」）作为进入下一阶段的条件；决策表、调度映射与停止条件的唯一真源为该文件，本 Skill SHALL NOT 内联其内容。

本阶段为**变更级**，衔接不涉及子变更遍历：变更内本阶段完成后，衔接决策对下一变更级阶段（审计 → `kflow-audit`）执行决策表。轻量档本阶段被判为 `⏭️ 不适用` 时直接进入审计阶段的既有规则不变，仍由本次衔接决策交回审计。

阶段自身的人工门控 SHALL 照常执行，SHALL NOT 被衔接决策跳过；自动衔接免除的仅为「提示用户输入推进指令」这一步。

## 与其他 Skill 的关系

- **输入来自**：
  - 前后端项目：`kflow-e2e-test`（所有子变更 E2E 测试通过后）
  - 纯后端项目：`kflow-api-test`（所有子变更接口单元测试通过后）
- **输出给**：`kflow-audit`（审计门控） → `kflow-archive`（归档）；轻量档本阶段被判定为 `⏭️ 不适用`（有声明依据）时 SHALL 直接输出给 `kflow-audit`，SHALL NOT 执行服务刷新与阶段钩子
- **前置阶段**：所有子变更编码+审查+测试通过（测试阶段可标记 `⏭️ 不适用`，须有声明依据）+ 服务刷新
- **后续阶段**：审计 → 归档
- **阶段衔接**：验收通过后执行阶段衔接决策（见 `skills/kflow-integration-test/references/phase-transition.md`），直接调度审计阶段 `kflow-audit`，SHALL NOT 提示用户输入推进指令；本阶段为变更级，不涉及子变更遍历
- **内聚功能**：变更级缺陷修复（四分法），不跳转到 `kflow-bug-fix`
- **服务管理**：变更级 agent 独占服务生命周期管理，集成测试执行前编译重启
- **关系说明**：`kflow-bug-fix` 仅处理子变更级缺陷修复（二分法），变更级修复由本 Skill 内聚处理
- **执行模式**：单轮全面执行 + 定向重验（仅重跑失败用例，有界重试，连续 3 次失败即终止；参见 skills/kflow-integration-test/references/repetition.md），终止结果取 `执行完成` / `定向重验失败`；审查范围冻结 + 范围外观察降级；复杂度评估仅信息展示，主 Agent 验收闭环
