# agent-iteration-execution Specification

## Purpose

定义执行类阶段的档位驱动收敛制迭代机制：执行轮次下限统一为 1 轮、上限由变更档位决定（轻量 1 / 标准 3 / 完整 5），以**见证轮**（零新发现 + 零修改 + 报告证明全量遍历）为收敛终止判据，涵盖复杂度评估、重复制子代理 prompt 规范与主 Agent 轮次验收规则，确保执行类阶段迭代充分且产物质量受控。

## Requirements

### Requirement: 执行类阶段按档位轮次上限迭代

所有执行类阶段（编码/代码审查/接口单元测试/E2E测试/集成测试/缺陷修复）SHALL 通过重复制子代理完成**不超过档位轮次上限**的迭代，轮次 SHALL 不少于全局下限 1 轮，并在达成收敛终止条件（最近一轮为见证轮）时提前结束。kflow-plan 阶段的迭代循环为产物自审，其轮次上限取设计自审口径（轻量 1 轮 / 标准 2 轮 / 完整 5 轮），迭代与验收机制不变。

#### Scenario: 执行类阶段设定档位轮次上限

- **WHEN** 任一执行类阶段启动重复制子代理
- **THEN** Agent MUST 在该档位轮次上限内完成迭代（执行类阶段：轻量 1 / 标准 3 / 完整 5；plan 阶段：轻量 1 / 标准 2 / 完整 5）
- **AND** 执行轮次 SHALL 不少于 1 轮
- **AND** 每轮完成时更新 .status.md 中 `执行轮次` 计数器
- **AND** 达成收敛终止条件或达到轮次上限后方可返回验收报告

#### Scenario: 有实际工作时正常迭代

- **WHEN** Agent 在当前轮次发现需要执行的工作（代码编写、测试执行、缺陷修复等）
- **THEN** Agent 执行该工作
- **AND** 记录执行结果
- **AND** 递增轮次计数器并进入下一轮（若未达轮次上限）

#### Scenario: 无实际工作时按收敛判定

- **WHEN** Agent 在当前轮次无新发现且无可执行工作
- **THEN** 该轮 SHALL 被判定为**见证轮候选**——须同时满足「零修改」且「报告证明全部工作项已完成全量遍历」
- **AND** 满足见证轮条件时 Agent SHALL 终止并返回验收报告
- **AND** 不满足见证轮条件时 Agent SHALL 递增计数器并继续下一轮
- **AND** SHALL NOT 为凑满轮次上限而执行无增量价值的轮次

#### Scenario: 收敛或达上限后返回

- **WHEN** Agent 在某轮达成见证轮，或执行轮次达到轮次上限
- **THEN** Agent SHALL 准备验收报告
- **AND** 报告 SHALL 记录终止原因（`收敛` / `达上限`）
- **AND** 返回主 Agent

### Requirement: 复杂度评估机制

系统 SHALL 在启动重复制子代理前评估任务复杂度，并将结果仅作为信息展示写入 .status.md 备注列。复杂度评估结果不驱动子代理执行行为——禁止将分级转化为按轮次分段分配工作重点的节奏指引。

#### Scenario: 基于可量化指标计算复杂度

- **WHEN** 评估阶段复杂性
- **THEN** 系统 MUST 按以下公式计算复杂度分：功能点数 × 1 + 接口数 × 1.5 + 场景数 × 2
- **AND** 将结果写入 .status.md 备注列作为背景信息，附带标注「仅供参考，不驱动执行行为」
- **AND** 分级阈值保留（低 <20 / 中 20-50 / 高 >50）但仅用于信息分类
- **AND** MUST NOT 将分级转化为节奏指引传递给子代理

#### Scenario: Agent 提前返回但未完成

- **WHEN** Agent 子代理返回但主 Agent 验收发现无见证轮且未达轮次上限，或产物不合格
- **THEN** 主 Agent 记录当前进度到 skill-suggestion.md
- **AND** 若无见证轮且未达轮次上限 → 直接要求 Agent 子代理继续执行剩余轮次，不进入 AskUserQuestion
- **AND** 若已达轮次上限但产物不合格 → 进入非收敛分支，询问用户是否重新启动 Agent 子代理

### Requirement: 重复制子代理 prompt 规范

系统 SHALL 为重复制子代理构建包含完整上下文的 prompt。Prompt SHALL 包含重复制遍历指令，SHALL NOT 包含节奏指引或按轮次分段分配工作重点的指令。

#### Scenario: prompt 内容要求

- **WHEN** 构建重复制子代理 prompt
- **THEN** prompt MUST 包含：
  - 当前阶段目标与产物要求
  - 输入文档引用（functional-designs/、detailed-design.md 等）
  - traceability.md 中待填充的列和覆盖率目标
  - 重复制遍历指令：「每轮遍历全部工作项独立执行完整流程。更新 .status.md 中执行轮次计数器为当前轮次号。禁止按轮次分段分配工作重点——每轮均须对全部工作项执行完整检查。执行轮次 SHALL 不少于 1 轮且不超过轮次上限；当某轮零新发现且零修改、且报告证明全部工作项已完成全量遍历时，该轮构成见证轮，SHALL 提前返回验收报告。达成收敛或达到轮次上限之前 SHALL NOT 无理由返回。」
  - 轮次上限的具体数值（由变更档位确定，轻量 1 / 标准 3 / 完整 5，不得硬编码为 10）
  - 轮间摘要（第 2 轮起注入，格式见 `inter-round-summary` 能力）
- **AND** prompt SHALL NOT 包含「前 N 轮重点执行/中间 N 轮细节优化/后 N 轮验证」等分段分配指令
- **AND** 复杂度评估结果可出现在 prompt 中但必须附带标注「仅供参考，不驱动执行行为」

#### Scenario: prompt 引用现有文档

- **WHEN** 子代理需要读取设计文档作为输入
- **THEN** prompt 中使用文档路径引用（非复制完整内容）
- **AND** 子代理通过 Read 工具自行读取所需文档

### Requirement: 主 Agent 轮次验收

系统 SHALL 在重复制子代理完成后由主 Agent 执行验收。

#### Scenario: 验收通过

- **WHEN** 主 Agent 检查以下条件全部满足：
  - .status.md 中 `执行轮次` >= 1 且（最近一轮为见证轮 或 `执行轮次` = 轮次上限）
  - 阶段产物文件存在且格式正确
  - traceability.md 对应列覆盖率 = 100%
  - 无 TODO/TBD/{待填写} 等占位符
- **THEN** 验收通过
- **AND** 更新 .status.md 中对应阶段状态为 ✅ 完成
- **AND** 门控释放，可进入下一阶段

#### Scenario: 验收不通过——无见证轮且未达上限

- **WHEN** 主 Agent 检查发现无任何一轮为见证轮 且 `执行轮次` < 轮次上限
- **THEN** 验收不通过
- **AND** 无见证轮且未达上限为硬性拒收条件，不接受 Agent 子代理任何理由的提前返回
- **AND** 系统记录到 skill-suggestion.md（包含阶段、当前轮次、轮次上限、建议：继续执行剩余轮次）
- **AND** 直接重新启动 Agent 子代理继续执行，不询问用户

#### Scenario: 验收不通过——达上限但产物不合格

- **WHEN** 主 Agent 检查发现 `执行轮次` = 轮次上限 但产物条件不满足（文件缺失、覆盖率不足、有占位符）
- **THEN** 验收不通过，进入非收敛分支
- **AND** 系统记录到 skill-suggestion.md（包含阶段、轮次上限、覆盖率缺口、建议）
- **AND** 使用 AskUserQuestion 询问用户：「验收不通过，是否重新启动重复制子代理？」
- **AND** 用户选择「是」→ 调整 prompt 后重新启动 Agent 子代理
- **AND** 用户选择「否」→ 标记 .status.md 为 ⚠️ 需修订，阻塞当前阶段

#### Scenario: 验收记录格式

- **WHEN** 验收不通过并记录到 skill-suggestion.md
- **THEN** 记录 MUST 包含以下字段：发现时间、发现阶段（Agent 验收）、触发场景、覆盖缺口详情、轮次信息（当前轮次/轮次上限）、终止原因、复杂度信息、改进建议、状态（待重跑）、优先级
