# Design

## Context

动机见 `proposal.md - Why`。约束：

- 该变更横跨 18 个 KFlow Skill 的 SKILL.md、10 份 `references/`（`self-review.md` × 3、`self-review-dimensions.md`、`repetition.md` × 8）、13 个 openspec 能力，以及 `docs/designs/skills/*.md` 设计文档。
- `phase-self-review` 能力要求三个设计技能的 `references/self-review.md` **内容一致**——任何改动必须三处同步。
- `tier-driven-repetition` 能力声明「影响范围分数到轮次的映射 SHALL 仅在本能力中定义一次」，但 `flexible-repetition-mode` 与 `execution-repetition-mode` 实际也各自表述了同一映射（既有重复）。
- `html-prototype-workflow` 的导航/Playwright 验证 requirement 与 `prototype-navigation-verification` / `prototype-playwright-5round-verification` 重复（既有重复）。
- 归档时 MODIFIED 块**不得遗漏或改名既有 scenario**（验证器强制），因此场景名含旧语义的 requirement 必须改用 REMOVED + ADDED。

## Goals / Non-Goals

**Goals:**

- 把三套口径（设计自审 / 执行类重复制 / prototype VERIFY）的终止条件统一为「下限 1 + 档位上限 + 见证轮收敛终止」
- 让「自然收敛」从声明变为可判定的机制（见证轮）
- 补齐「达上限仍未收敛」的失败分支，使上限成为有效信号而非静默放行点
- 消除三处既有规格重复与两处规格漂移（`round-counter` 的 `{N}/10`、`agent-iteration-execution` 的 Purpose）

**Non-Goals:**

- 不改动审查**维度**（完整性/闭环性/必要性/清晰性等）与交叉审查视角分级（`design-review-tiering` 未纳入 delta）
- 不改动轻量档的**阶段裁剪**逻辑（`lightweight-flow-trimming` 未纳入 delta）
- 不引入新的 Skill 或新的阶段
- 不改变变更档位（轻量/标准/完整）的判定规则本身

## Decisions

### D1 档位语义由「下限」翻转为「上限」，全局下限统一 1

`tier-driven-repetition` 自身已把 `1/3/10` 写作「档位基线（目标轮次的下限）」，而各 SKILL 与 references 把它当「强制完成数」。本变更统一到规格自身措辞，并把完整档上限由 10 降为 5。

- **替代方案 A（档位=下限、上限另设 15）**：完整档下限仍为 10 = 上限，最贵的档位反而无法提前终止，与目标矛盾。否决。
- **替代方案 B（仅消除 0 轮，完整档仍硬下限 10）**：改动最小但收益最低。否决。
- **选定方案**：`轻量 [1,1] / 标准 [1,2 设计·1,3 执行] / 完整 [1,5]`，数字沿用既有基线（除完整档 10→5），语义翻转。**代价**：完整档可能在极早轮次终止，故绑定 D3、D4 的三道闸。

### D2 下限统一为 1（无例外）

决策来自用户明确要求：「所有档位都统一调整为下限 1 轮次」。这条把「至少审查一轮」变成全局不变量，并**顺带修复既有缺口**：原轻量档设计自审为 0 轮，语义审查完全缺失，仅有占位符形式检查。

### D3 收敛判据 = 见证轮（1 轮）

见证轮定义为「零新发现 + 零修改 + 报告证明全维度全量遍历」。

- **推导**：下限 = 1 且终止需「下限达成 ∧ 见证轮」⇒ 若要求「连续 2 轮见证」，最小可终止轮次变为 2，与「下限统一 1」矛盾。故见证轮为 **1 轮**。此结论由 D2 直接推出，无需单独决策。
- **反空转**：第三项条件（报告证明全量遍历）用于阻止「空转轮」被误判为见证轮。
- **独立见证**：见证轮候选必须复核前轮全部修复（见 D5），避免「同一轮既改又评」的自评分偏差。

### D4 前提绑定：轮间摘要注入扩展到设计自审

移除「必须完成全部轮次」= 用「一个可信的零发现」替换「N 倍冗余复扫」。冷启动子代理的「零发现」可能只是遗漏而非收敛，因此：

```
  冗余统计防线  →  结构收敛防线
  (扫 10 遍碰运气)   (轮间因果，收敛可证明)
        ↑                    ↑
        │              依赖轮间摘要传递
        └── 移除后防线被削弱；补上摘要才能替代
```

故 **D1/D2 的移除与轮间摘要扩展在设计上不可分割**，二者须同期落地。该机制为执行类既有（`repetition.md` §13 / `inter-round-summary` 能力），本变更只是**解除其被分层加载规则排除在设计类之外**的现状，不发明新机制。

### D5 完整档评分底线由装饰变为有效

原规则两头都够不着：第 3 轮 >8 仍须做满 10 轮；第 10 轮 ≤8 已无处补审。翻转后语义变为「`>8` 且收敛即止，`≤8` 续审至上限 5」，底线首次生效。

### D6 回退重执行叠加规则反向

原 `目标轮次 = max(档位基线, 影响范围映射)` 建立在「档位 = 下限」上。翻转后必须反向为 **`上限 = max(档位上限, 影响范围映射)`**，否则轻量档回退时 `max(1, 3)` 无处可加，返工被 1 轮上限卡死，违背规格「返工验证不因低档而放松」的原意。影响范围映射同步更新：`>15 → 5`（原 10）。

### D7 非收敛分支对齐执行类既有模式

达上限仍无见证轮 → `skill-suggestion.md` + AskUserQuestion → 可标记 ⚠️ 阻塞。与 `repetition.md` §9 既有模式一致，不新增范式。同时 `.status.md` 新增**终止原因**字段（`收敛` / `达上限`），使审计可判读「为何停在第 4 轮」。

### D8 规格去重（本变更顺带修掉的既有重复）

| 重复项 | 处理 |
|--------|------|
| `html-prototype-workflow` 的导航/Playwright 验证 requirement 与两个 `prototype-*` 专门能力重复 | REMOVED 两条，改为一条「原型验证轮次的统一引用」，轮次规则单一来源 |
| `flexible-repetition-mode` / `execution-repetition-mode` 各自表述影响范围映射，与 `tier-driven-repetition`「仅定义一次」矛盾 | 本变更将三者数值同步为 `>15→5`；映射权威仍在 `tier-driven-repetition`，其余能力改为引用表述 |

## Risks / Trade-offs

- **[完整档可能过早终止]** → 三道闸：下限 1 + 见证轮三条件 + 评分 `>8`；且上限 5 仍高于典型收敛轮次。
- **[冷启动的「零发现」不可信]** → 强制绑定 D4（轮间摘要），见证轮须复核前轮修复。
- **[轻量档新增 1 轮自审，成本上升]** → 收益是补上原本完全缺失的语义审查；1 轮为最小代价。
- **[残留文本未清干净]** → 全仓存在「完成全部 5 轮 / 10 轮」「不允许提前终止」等散落表述，须由 tasks 显式覆盖全仓清理，否则规格与实现不一致。
- **[去重改变能力边界]** → `html-prototype-workflow` 移出两条 requirement；若下游（如 `devflow-audit` 的产物检查）按该能力清单核对，需同步确认（列入 tasks）。
- **[审计/门控适配]** → 审计须接受「终止原因 = 收敛且轮次 < 上限」为合法；否则会因轮次未满而误判缺项。

## Migration Plan

1. **规格层**（本变更的 delta，归档时应用）：13 个能力的 ADDED/MODIFIED/REMOVED。
2. **实现层**：同步 `skills/kflow-*/SKILL.md` 与 `references/`（`self-review.md` × 3 必须一致、`repetition.md` × 8、`self-review-dimensions.md`）。
3. **设计文档层**：同步 `docs/designs/skills/kflow-*.md`。
4. **残余清理层**：全仓消除「完成全部目标轮次 / 完成全部 5 轮 / 不允许提前终止」类表述；修正 `agent-iteration-execution` 与 `plan-self-review` 等能力 Purpose 段中的「强制 10 轮」「5 轮」漂移。
5. **回滚策略**：本变更为文档/规格级，无运行时状态；回滚 = 还原上述文件。已归档变更中依 `终止原因` 记录的轮次数据不受影响。
