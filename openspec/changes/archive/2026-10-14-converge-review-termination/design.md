# Design

## Context

见 `proposal.md` 的 Why。设计层面需要承接的现状约束：

- 终止模型分散在 4 个权威位置：`tier-driven-repetition`（轮次上限、映射表、评分底线）、`recheck-round`（终止点追加轮）、`agent-iteration-execution`（迭代与验收）、`round-counter`（计数器格式与验收判据）。四者的判据互相咬合，任一处改动都会牵动其余三处与 16 份派生能力。
- 「见证轮」概念已存在且语义稳定（零新发现 + 零修改 + 全量遍历证明），本变更是在其上做**收口**而非重造。
- 主 Agent 已在维护轮间摘要与「累积未复核修复清单」（`repetition.md` §13.7），新增判据所需的观测数据（每轮新发现数、清单长度）天然由该载体提供，不需要新的采集机制。
- 实现层是 markdown 规格文件（8 份 `references/repetition.md`、10 份 `references/gates.md`、3 份 `references/self-review.md`、14 份 `SKILL.md`），无运行时代码、无数据迁移。

## Goals / Non-Goals

**Goals:**

- 把「收敛」确立为唯一成功终止条件，并把让收敛**可达**的前提（审查范围冻结）写入规格，使两者的规格归属相邻、可一并验证。
- 删除因「上限」而生的整条派生链（回退叠加、分数→轮次映射、复检轮、份数判读链、三值终止原因），净减机制数量。
- 让「不收敛」成为一个**显式、可判读、有缘由**的失败终止，而不是一个数值耗尽后的副产品。

**Non-Goals:**

- 不改动单用例 3 次修复上限（`defect-strike-limit`）与轮次级子代理崩溃重试 3 次上限——二者与轮次上限是正交维度。
- 不改动各阶段的审查维度枚举与检查项内容（本变更只封闭维度集合，不增删维度本身）。
- 不改动档位对审查形态（单 Agent / 两视角 / 四视角）与产出深度的映射。
- 不重命名 `prototype-playwright-5round-verification`（见 Decisions 第 9 条）。
- 不引入基于 token 或时间的成本预算制——Claude Code skill 层无法精确读取该量，不可实现。

## Decisions

### 1. 用「不收敛判定」替换「轮次上限」，而非纯收敛无兜底

**选择**：成功终止 = 见证轮；失败终止 = 不收敛判定命中后升级用户。上限降级为一条与档位脱钩的全局安全丝。

**理由**：上限在正常路径上是惰性的（收敛提前终止），它唯一的作用是处理不收敛。删掉它必须回答"不收敛怎么办"，否则循环会跑到会话边界硬停——那是崩溃而非设计终止。

**备选**：① 纯收敛、无任何兜底——最简洁，但失去全部机器侧终止保证，且没有任何机制会在卡住时问人；② 保留档位上限作为安全丝——等于没删，档位仍决定轮数。均否决。

### 2. 不收敛判据用「双指标 + 连续 2 轮」，不用单指标或阈值

**选择**：无进展 = 连续 2 轮「本轮新发现数」**且**「累积未复核修复清单长度」双双不低于其前一轮。振荡按问题项标识追踪「修复 → 重新发现」累计 ≥ 2 次。

**理由**：单看发现数会误伤慢收敛——清单在缩短但发现数持平时，循环正在收敛而非停滞，双指标同时无改善才是真停滞。按问题项标识判振荡，可以捕获"修 A 打回 B"这类发现数恒定但实际空转的形态。

**备选**：① 单指标（发现数）——误伤慢收敛；② 设置下降比例阈值（如"发现数下降 < 20%"）——阈值本身是一个新的魔法数，与"删除魔法数"的目标相悖。均否决。

### 3. 安全丝取全局 10 轮，与档位脱钩且不参与门控判读

**选择**：该阶段审查轮数达到 10 轮即判不收敛。安全丝不随档位变化，不写入门控或审计的判据。

**理由**：现状完整档上限就是 5，10 足够"远离常态"，正常路径永远碰不到；保留一个绝对有界的保险丝，避免 LLM 审查循环彻底失控。与档位脱钩是为了不让档位重新获得轮次语义。

**备选**：随档位取值——档位重回轮次语义，与决策 1 冲突。否决。

### 4. 复检轮上提为见证轮第 (d) 项，而非保留独立机制

**选择**：把「清单内全部未复核修复逐项复核通过」写进见证轮定义的正式第 (d) 项，删除 `recheck-round` 能力、复检轮报告、`收敛（复检轮）` 终止原因与份数判读链。

**理由**：复检轮的**通过判据本来就是「构成见证轮」**，而见证轮候选按既有复核义务已经必须逐项复核清单内全部条目——(d) 项其实早已存在，只是写在 `repetition.md` §13.5 而不是见证轮定义里。上限删除后，「清单非空却终止」这条路消失，复检轮成为不可达的死代码。上提比保留更省机制，且把复核义务放到了它本该在的位置（权威判据里，而非轮间摘要的执行细节里）。

**备选**：保留复检轮并为其重新设计触发条件（如"不收敛终止时也复核"）——会引入"复检轮自身未通过 → 然后呢"的二次兜底，而无上限模型下该二次兜底无处安放。否决。

### 5. 终止结果改二值 `收敛` / `未收敛`，缘由外移

**选择**：`.status.md` 写「终止结果」二值；具体缘由（无进展 / 振荡 / 安全丝）写入 `docs/skill-suggestion.md`。

**理由**：`达上限` 在上限删除后不可达；`收敛（复检轮）` 随复检轮消失。二值让审计的判读从"枚举 + 份数推导"简化为"读一个字段 + 检查未收敛是否有升级记录"。缘由是诊断信息而非状态机取值，放 `skill-suggestion.md` 更贴合它既有的用途（记录需要用户关注的事项）。

**备选**：保留三值并让第三值表示"未收敛缘由"——把诊断信息塞进状态机字段，且会引出新的枚举组合。否决。

### 6. 审查范围冻结按「轮」生效，由主 Agent 执行

**选择**：每轮开始时由主 Agent 从阶段产物既有内容生成本轮审查对象清单并注入 prompt，轮内不可扩大；跨轮可因阶段输入变化（回退重执行新增受影响项）由主 Agent 更新。

**理由**：全阶段单向冻结会与回退机制冲突——回退恰恰要带来新的受影响项。把冻结的时点定在"轮"，并把跨轮更新的执行权归主 Agent，既保证子代理无法自行扩边，又不阻断阶段输入变化。

**备选**：① 全阶段冻结——与回退冲突；② 限制每轮发现数量——会迫使审查者放弃真实问题，且数量上限又是一个魔法数。均否决。

### 7. 范围外发现的落点是审查报告小节 + 阶段终止汇总，不新增文件

**选择**：写入该轮审查报告的「范围外观察」小节；主 Agent 在阶段终止时汇总并向用户提示。不修改任何正式产物，不计入发现数，不阻断收敛。

**理由**：不设出口的范围冻结会变成"漏掉真问题"。降级为观察既保住收敛可达性，又不丢弃信息。不新增文件是因为审查报告本就含「仍存在问题」等自由小节，载体已存在。与审计侧「建议级问题不阻断归档」是同一个模式。

**另外**：在轮间摘要中新增「范围外观察」字段，使后续轮次不会重复发现同一范围外内容——重复发现会消耗轮次而不产生进展，直接削弱无进展判据的可达性。

**备选**：写入 `skill-suggestion.md`——该文件语义是"对 skill 本身的改进建议"，范围外发现（如"隔壁模块有缺陷"）不属于该语义。否决。

### 8. 完整档评分底线内化，不新增"评分停滞"兜底

**选择**：规定评分 ≤8 时该轮须列出对应具体问题项，使「评分 ≤8」等价于「存在新发现」，从而自然不构成见证轮。

**理由**：删除"或达上限 5"后，"零发现但评分 ≤8"会变成自洽的无限循环态。内化消除了这个状态——评分低就必须给出问题，有问题就不是零发现。不新增机制，也不引入第二套终止条件。

**备选**：为评分增设独立的停滞检测——新增机制，且与决策 2 的不收敛判据职责重叠。否决。

### 9. 能力改名范围：只改 `tier-driven-repetition`

**选择**：`tier-driven-repetition` → `convergence-driven-repetition`。`prototype-playwright-5round-verification` 保持 id 不变（名字含已失效的 `5round` 语义）。

**理由**：前者是能力的**主题**变了（不再由档位驱动轮次），必须改名否则名实不符；后者在 `converge-review-rounds` 变更中就已从"固定 5 轮"改为 `[1,5]` 收敛驱动，当时选择容忍陈旧名字，本次沿用该先例以控制改动面。

**备选**：两个都改名——一致性更好但 churn 更大，且与既有先例不一致。已在 proposal 的「假设」中标注，可由用户在评审时推翻。

### 10. `执行轮次` 字段改 `{N} 轮`，读取侧兼容旧格式

**选择**：新写入 `1 轮` / `2 轮`；读取侧遇到历史 `{N} / {上限}` 时取分子、忽略分母。

**理由**：分母来自已删除的档位上限，保留即保留一个无意义的魔法数。读取侧兼容让历史变更的 `.status.md` 无需迁移。

**备选**：保留 `{N} / {上限}` 格式但把分母固定为某个值——保留了魔法数。否决。

### 11. 变更文档（`docs/designs/`）与主 spec 的 Purpose 段同批更新，作为实现任务

**选择**：把 `docs/designs/` 的同步、以及各能力主 spec 中 `## Purpose` 段的同步，写入 `tasks.md` 作为实现任务。

**理由**：主 spec 的 `## Purpose` 无 delta 通道（delta 的 Purpose 对既有能力被忽略），只能在主 spec 内直接改；把该改动与其余实现步骤放在同一批执行，可让主 spec 与 delta 在同一时点收敛，避免规划期就产生主 spec 与 delta 不一致的中间态。

## Risks / Trade-offs

- **[收敛判据依赖子代理自述，子代理可能"声称"收敛或编造范围内问题以延续/提前结束]** → 反空转条款保留：未证明全量遍历的零发现不采信；见证轮的「零修改」判定以**产物文件差异**为准（优先级高于子代理自述）；主 Agent 以产物事实裁决。
- **[范围冻结可能导致范围外的真实问题被搁置]** → 范围外观察不丢弃，主 Agent 在阶段终止时汇总提示用户，用户可据此另起变更。
- **[慢收敛的真实成本上升]**（发现上限删除后，原本被上限截断的循环会继续） → 这正是变更的目的（避免误伤本会收敛的循环）；成本可见性由审计的终止结果字段提供。若审计显示某类阶段长期需要多轮，那是有价值的信号而非异常。
- **[无进展判据需要主 Agent 逐轮维护两项计数]** → 复用既有载体：每轮新发现数取自审查报告，清单长度由主 Agent 已在维护的轮间摘要字段提供（`repetition.md` §13.7），不新增采集机制。
- **[审计失去「轮次 vs 上限」这一观测量]** → 审计改读终止结果字段，并检查 `未收敛` 阶段是否有对应升级记录；「轮次偏多」不再是一个可判定的偏差类型（不再有基准），改为关注"未收敛是否被正确处理"。
- **[历史 `.status.md` 的兼容]** → 三值终止原因在读取侧归并为二值（`收敛（复检轮）` → `收敛`，`达上限` → `未收敛`）；`执行轮次` 忽略分母。两处均为读取侧适配，不要求迁移历史文件。
- **[能力改名导致引用漏改]** → 实现任务中列入全量引用扫描（`openspec/specs/`、`skills/`、`docs/designs/`、`README.md`），并以 `scripts/sync-references.sh` 校验一致性。

## Migration Plan

本变更无运行时数据、无部署步骤，迁移即文档与规格的同批更新：

1. 更新 `openspec/specs/` 主 spec：删除 `tier-driven-repetition/` 与 `recheck-round/`，新增 `convergence-driven-repetition/`，应用 23 份既有能力 delta。
2. 同步各受影响主 spec 的 `## Purpose` 段（无 delta 通道，需在主 spec 内直接改）。
3. 更新实现层：8 份 `references/repetition.md`、10 份 `references/gates.md`、3 份 `references/self-review.md`、`references/self-review-dimensions.md`、14 份 `SKILL.md`，八份 `repetition.md` 与三份 `self-review.md` 须内部一致。
4. 更新 `docs/designs/`（`core-mechanisms/03`、`04`、`07`、`index.md` 与相关 `skills/kflow-*.md`）与 `README.md`。
5. 运行 `scripts/sync-references.sh` 校验引用一致性。

**回滚策略**：变更全部落在 markdown 规格与文档，回滚即回退上述文件；无状态迁移、无破坏性操作。若仅需保留旧行为，恢复 `tier-driven-repetition` 与 `recheck-round` 两份主 spec 即可还原终止模型的权威定义。
