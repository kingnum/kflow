# Design

## Context

动机与缺口论证见 `proposal.md`（Why、What Changes）。本设计只处理"如何落地"及其技术取舍。

塑造方案的既有约束：

- **规则以多份自包含拷贝存在**。同一套轮次模型在 8 份 `skills/kflow-*/references/repetition.md`（执行类 7 份 + plan 1 份）与 3 份 `skills/kflow-{explore,design,prototype-design}/references/self-review.md` 中各自成文。`phase-self-review` 要求三份 `self-review.md` 内容**完全一致**；8 份 `repetition.md` 历史上也是字节级一致的拷贝。
- **终止原因字段已被广泛读取**。`.status.md` 的 `终止原因` 取值 `收敛` / `达上限`，被 8 份 `repetition.md` §14.5/§15、`kflow-audit/SKILL.md`、`kflow-resume/SKILL.md` 与 10 份 `references/gates.md` 读取或校验。
- **`执行轮次` 字段格式已定型**。`round-counter` 规定其为 `{N} / {上限}`，写入变更级与子变更级 `.status.md` 的「基本信息」区。
- **既有表述分歧**：`round-counter` 的「达上限验收」把 `执行轮次 = {上限}/{上限}` 且产物齐全判为**验收通过**（终止原因 `达上限`），而 `repetition.md` §9 类型 B 把「达上限仍无见证轮」判入**非收敛分支**。两者可共存解释为「轮次维度通过、产物/收敛维度处理」，但文本确有张力。本变更**不放大也不重构**该分歧。

## Goals / Non-Goals

**Goals:**

- 使「任何被记入审查报告的修复都经过独立验证」成为阶段终止的必要条件。
- 消除轻量档「正常发现并修复了问题」被记为「非收敛」异常的语义倒挂。
- 复检轮的规则**单点定义、其余引用**，避免在 8+3 份拷贝中各自漂移。

**Non-Goals:**

- 不改动交叉审查侧（`review-closed-loop`）。其验证由"批次"事件驱动、无轮次上限制，本就不存在该缺口；本次仅建立术语对齐（统一用「复检」一词）。
- 不改变各档位的审查强度。档位轮次上限表（设计自审 1/2/5、执行类 1/3/5）保持不变。
- 不重构 `repetition.md` 与 `flexible-repetition-mode` 之间的既有规则冗余。
- 不引入「修复后必须重走完整审查轮」——复检轮只做验证，不重新发现、不重新修复。

## Decisions

### D1：复检轮不消耗档位轮次预算

复检轮追加在档位轮次上限之外，全局最多 1 轮。轻量档因此实际执行 1~2 轮。

替代方案与否决理由：

- **消耗预算**：轻量档上限为 1，第 1 轮修完已无剩余轮次，规则对最需要它的档位无效，还得为轻量档单独破例。
- **上限内保留末轮作为验证轮**：等价于把上限降低 1，直接削弱各档位审查强度。

### D2：复检轮通过判据复用见证轮定义

复检轮通过 `==` 该轮构成见证轮（零新发现 + 零修改 + 全量遍历 + 清单内全部修复逐项复核通过）。不发明第二套判据。

理由：收敛语义保持单一，规则总数不增加，反空转条款（未证明全量遍历不得判定为见证轮）自动适用于复检轮。

替代方案：为复检轮定义独立的「复核通过」判据。否决——增加一个与见证轮高度重叠的概念，读者需同时维护两套条件。

### D3：终止原因扩为三值

取值 `收敛` / `收敛（复检轮）` / `达上限`。

**判读链**（门控与审计据此工作，无需新增字段）：

```
   终止原因              报告份数            推导结论
   ------------------    ----------------    ---------------------------
   收敛                  <= 档位上限         预算内收敛（末轮为见证轮）
   收敛（复检轮）         = 档位上限 + 1      复检轮已执行且通过
   达上限                 = 档位上限 + 1      复检轮已执行且未通过
   达上限                <= 档位上限         复检轮未触发（清单为空）
```

替代方案：保持二值 + 新增独立「复检轮」字段（未触发/通过/不通过）。否决——审计需组合两个字段才能判读，且新增字段本身要写入门控与审计的校验逻辑，改动量反而更大。

### D4：`执行轮次` 字段格式不变

保持 `{N} / {上限}`，只记录审查轮；复检轮不改写该字段。复检轮的存在完全由 `终止原因` 蕴含（见 D3 判读链）。

理由：避免 BREAKING；历史 `.status.md` 的读取路径不变。

### D5：命名「复检轮」

对齐 `review-closed-loop` 已使用的「单轮复检」表述，使自审侧与交叉审查侧共享同一术语。「验证轮」会与 prototype 阶段的 VERIFY 步骤（nav-check / playwright-check）撞名，故不用。

### D6：累积未复核修复清单由主 Agent 维护

清单的维护责任落在**主 Agent**，不入子代理的职责。载体为轮间摘要的固定字段（`inter-round-summary`），并在终止判定时读出。

理由：`self-review.md` §8 已确立「见证轮判定由主 Agent 执行，且 (b) 零修改的判定以产物文件差异为准」。清单是该判定的输入，须与判定同源，否则子代理自述与产物事实冲突时无法裁决。

各轮末尾的增量规则：

```
   清单(第 N 轮结束) = 清单(第 N-1 轮结束)
                     + 第 N 轮新增的修复
                     - 第 N 轮实际复核通过的修复
```

### D7：报告命名分两套

- **设计自审侧**（explore / design / prototype-design / plan）：沿用时间戳 `{YYYYMMDD}-{HHMMSS}.md`，复检轮不另加后缀，报告内标注「复检轮」。理由：该体系以"自然排序即时间序"为约定，复检轮时间上在最后，排序自然落到末尾；加后缀会破坏该约定的统一性。
- **prototype VERIFY 侧**（nav-check / playwright-check）：复检轮报告命名为 `round-recheck.md`。理由：该体系用 `round-{N}.md`，N 为轮次 1–5；复检轮不计入该序列，若编为 `round-6.md` 会与"上限 5"冲突。UX 检查（ux-check）同构处理。

### D8：门控份数判定规则

`self-reviews/{phase}/` 的报告份数 SHALL 满足：

```
   份数 <= 档位上限                    （终止原因为 收敛 或 达上限）
   份数 =  档位上限 + 1                （终止原因为 收敛（复检轮） 或 达上限）
   份数 >  档位上限 + 1   ->  判违规
   份数 =  档位上限 + 1 但终止原因不含复检轮语义  ->  判违规（防滥用）
```

即"多出的那 1 份"必须能由终止原因解释，否则视为轮次超标。

### D9：修正三份 `self-review.md` 的悬空引用

三份文件（`kflow-explore` / `kflow-design` / `kflow-prototype-design`）的 `references/self-review.md` 第 23/143/175 行引用 `references/repetition.md` §13，但三者目录下均无 `repetition.md`。

修正方式：把轮间摘要的格式与注入规则**内联**到三份 `self-review.md`（新增章节），并删除悬空引用。

替代方案：在三份技能目录下各补一份 `repetition.md`。否决——设计类技能不含"执行类重复制"内容，新建同名文件会与执行类 `repetition.md` 的语义冲突，且同一份摘要规则会出现三份拷贝（正是本变更要消除的模式）。内联进 `self-review.md` 同时满足"自包含"与"三份一致"两条要求。

### D10：既有表述分歧保持原样

`round-counter` 的「达上限验收」与 `repetition.md` §9 类型 B 的张力（见 Context）不在本变更处理范围内。本变更只在 `round-counter` 的「轮次验收判据」中插入复检轮分支，保留其既有语义。

## Risks / Trade-offs

- [主 Agent 漏记修复，导致复检轮清单不完整] → 复检轮要求逐项复核并证明全量遍历；漏记会使复检轮无法证明覆盖，从而被判定未通过并进入非收敛分支，缺陷暴露而非静默。
- [8 份 `repetition.md` 与 3 份 `self-review.md` 在批量修改中漂移] → 沿用历史做法：先改 1 份作为基准，其余按字节级 `diff` 同步；tasks 中设置一致性验证项。
- [`收敛（复检轮）` 对未同步更新的读取方是未知取值] → tasks 覆盖全部读取点：8 份 `repetition.md` §14.5/§15、10 份 `gates.md`、`kflow-audit/SKILL.md`、`kflow-resume/SKILL.md`、`README.md`。
- [轻量档实际执行 2 轮，被误读为超出档位] → D3 判读链与 D8 份数规则显式允许 `上限 + 1`；审计侧（`kflow-audit/SKILL.md` 三处判定）同步加入该合法分支。
- [复检轮未通过时已无剩余轮次，修复需用户决策，可能形成往返] → 这是非收敛分支的既有定位；且当复检轮才暴露失败时，说明缺陷确实需要人工判断，升级是正确行为。
- [悬空引用内联后，三份 `self-review.md` 的公共章节体积增长] → 仅新增 1 个小节（清单字段 + 注入规则），且删除了 3 处悬空引用行。

## Migration Plan

- 本变更为规则与文档层变更，无运行时代码、无数据迁移。
- 历史变更的 `.status.md` 不含新取值，按既有缺省读取（缺失字段按 `完整` 档处理的既有规则不受影响）。
- 回滚策略：还原受影响的 `skills/`、`docs/designs/`、`openspec/specs/`、`README.md` 文件即可；无状态迁移需回退。
- 版本、打包、归档等元工作流由仓库既有流程驱动，不列入本变更的 tasks。
