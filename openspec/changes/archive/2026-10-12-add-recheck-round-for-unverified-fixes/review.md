## 7.3 轻量档样例走查（档位轮次上限 1）

| 步骤 | 第 1 轮零发现零修改 | 第 1 轮含 1 项修复（复检轮通过） | 第 1 轮含 1 项修复（复检轮未通过） |
|------|--------------------|--------------------------------|----------------------------------|
| 第 1 轮结果 | 零新发现 + 零修改 + 报告证明全维全量遍历 → **见证轮** | 发现并修复 1 项 → 非见证轮 | 发现并修复 1 项 → 非见证轮 |
| 主 Agent 更新「累积未复核修复清单」 | 空 | 非空（1 条） | 非空（1 条） |
| 到达终止点？（见证轮 ∨ 轮次 = 上限 1） | 是 | 是 | 是 |
| 终止点判定（§14.5 第一步） | 清单为空 → 按现行规则终止 | 清单非空 → **追加 1 轮复检轮**（不占上限） | 同左 |
| 复检轮结果 | — | 构成见证轮（零新发现 + 零修改 + 全量遍历 + 清单内 1 条逐项复核通过） | 未构成（复核不通过 / 未证明全量遍历） |
| 终止原因 | `收敛` | `收敛（复检轮）` | `达上限` → 非收敛分支（记录 `skill-suggestion.md` + AskUserQuestion，含复核失败详情） |
| `执行轮次` 字段 | `1 / 1` | `1 / 1`（复检轮不计入） | `1 / 1`（复检轮不计入） |
| `self-reviews/{phase}/` 份数 | 1 | 2 | 2 |
| 门控判定（`gates.md` §1.3） | 1 ≤ 上限 1 → 通过 | 2 = 上限 1 + 1 且终止原因含复检轮语义 → 通过 | 2 = 上限 1 + 1 且终止原因含复检轮语义 → 通过（该阶段已按规则进入非收敛分支，份数仍合法） |
| 审计判定（`kflow-audit` 三处） | 不判偏差 | 不判轮次不足/超额/缺项 | 不判轮次不足/超额/缺项；按「已升级用户决策」评估 |

**结论（不存在「发现即非收敛」路径）**：旧规则下轻量档第 1 轮只要有修复，该轮即非见证轮且轮次已达上限 1，系统立即判 `达上限` 并滑入非收敛分支——「正常发现并修复了问题」被记为异常态。更新后的规则在终止点插入了「先判清单、再分支」：第 1 轮含修复只会导向 1 轮复检轮，**仅当复检轮自身未通过时**才落入非收敛分支。走查确认三档路径中不存在「第 1 轮发现并修复 → 直接非收敛」的分支。

## 7.4 完整档样例走查（档位轮次上限 5）

**推演前提**：第 1~5 轮每轮均产生修复，无任何一轮满足「零新发现且零修改」，故无见证轮触发。

| 步骤 | 结果 | 对照依据 |
|------|------|---------|
| 轮次 1~5 | 每轮均发现并修复；清单每轮累加（第 N 轮结束 = 前轮剩余 + 第 N 轮新增修复 − 第 N 轮实际复核通过的修复）。因无轮为见证轮候选，累计 5 轮全部修复 | `inter-round-summary` §13.7 增量规则 |
| 第 5 轮结束 | `执行轮次` = `5 / 5` = 轮次上限 → 到达终止点 | §14.5 第二步表 |
| 终止点判定 | 清单非空（第 1~5 轮全部修复）→ 追加 1 轮复检轮，SHALL NOT 在此时进入非收敛分支 | §14.5 第一步 + §14.5.1 触发 |
| 复检轮复核范围 | 逐项复核第 1~5 轮**全部累积修复**（不限于第 5 轮）；已在前序轮次通过独立复核的修复不在清单内 | `recheck-round` 复核范围需求；§14.5.1 |
| 复检轮结果 | 构成见证轮（零新发现 + 零修改 + 报告证明全维全量遍历 + 清单内全部条目逐项复核通过） | §14.5.1 通过判据 |
| 终止原因 | `收敛（复检轮）` | §14.5 复检轮的终止 |
| `执行轮次` 字段 | 保持 `5 / 5`（复检轮不改写分子与分母） | design D4；`round-counter` |
| 报告份数 | 6（= 档位上限 5 + 1） | design D8 第 2 条 |
| 验证门控（§15.4） | 受影响项 100% 覆盖：仍须满足；全量 ≥1 轮兜底：**由复检轮的全量遍历证明满足**；产物完整性：复检轮报告作为附加产物存在且格式合规 → 通过 | §15.4 复检轮场景的门控判定 |
| 门控判定（`gates.md` §1.3） | 6 = 上限 5 + 1 且终止原因含复检轮语义 → 合法，不判违规 | design D8 |
| 审计判定 | 终止原因 `收敛（复检轮）` 属合法分支；份数 6 由终止原因解释 → 不判轮次不足、超额或缺项 | `kflow-audit` §效率与改进 / §流程与产物合规性 / §档位基准 |

**对照 design D3 判读链**：`收敛（复检轮）` + 报告份数 = 档位上限 + 1 → 推导结论「复检轮已执行且通过」✓（与 D3 表格第 2 行一致）。

**对照 design D8 份数规则**：份数 6 命中第 2 条（`份数 = 档位上限 + 1`，终止原因 `收敛（复检轮）`）；未命中第 3 条（不超过上限 + 1）与第 4 条（终止原因含复检轮语义，非滥用）✓。

**反证（防滥用条款生效）**：若同一场景下终止原因为 `收敛` 或 `达上限` 而未执行复检轮，则份数 6 命中 D8 第 4 条 → 判违规（轮次超标）✓。

## 7.5 prototype 人工审查路径走查

| 检查点 | 结果 |
|--------|------|
| `skills/kflow-prototype-design/SKILL.md` 前置条件段 | 审查方式为「人工审查」时 SHALL 完全跳过 SELFREV，**不计算轮次上限**（SHALL NOT 读取变更档位计算轮次），SHALL NOT 保留兜底轮次，**SHALL NOT 追加复检轮**，直接进入步骤 11 REVIEW ✓ |
| 同上 §9 VERIFY 强制执行规则 | 复检轮仅在「子代理自动审查验证」路径追加；「人工审查」路径 SHALL NOT 追加 ✓ |
| 同上 §10 与 VERIFY/SELFREV 对比表 | 触发条件行两侧均标注「人工审查」路径 SHALL NOT 追加复检轮 ✓ |
| 同上核心提醒 | 「条件说明」条明确复检轮仅在自动验证路径生效；「人工审查」路径完全跳过且不追加复检轮 ✓ |
| `README.md` 原型设计段 | 「人工审查（跳过全部自动验证、SHALL NOT 追加复检轮）」✓ |
| 规格依据 | `subagent-self-review`、`prototype-navigation-verification`、`prototype-playwright-5round-verification` 的 delta 均含「人工审查 → SHALL NOT 追加复检轮」场景 ✓ |

**结论**：人工审查路径下 SELFREV 与 VERIFY 全流程跳过，复检轮作为二者的终止点追加环节同样不触发；「人工审查」SHALL NOT 追加复检轮在规格、SKILL.md 与 README 三处一致。

## 走查结论

- 7.3：轻量档不再存在「发现即非收敛」路径；第 1 轮含修复 → 复检轮 → 通过 `收敛（复检轮）`（2 份）/ 未通过 `达上限`（2 份 + 非收敛分支）。
- 7.4：完整档 5 轮均含修复时，复检轮逐项复核全部累积修复；份数 6 = 上限 + 1，终止原因 `收敛（复检轮）`；门控与审计均不判违规。
- 7.5：prototype 人工审查路径 SHALL NOT 追加复检轮，规格、SKILL.md 与 README 一致。
