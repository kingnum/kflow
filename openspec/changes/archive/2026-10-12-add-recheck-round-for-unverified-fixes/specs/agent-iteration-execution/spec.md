# Spec Delta

## MODIFIED Requirements

### Requirement: 主 Agent 轮次验收

系统 SHALL 在重复制子代理完成后由主 Agent 执行验收。验收 SHALL 包含终止点复检轮判定：到达终止点时累积未复核修复清单非空且未追加复检轮时，验收 SHALL NOT 通过。

#### Scenario: 验收通过

- **WHEN** 主 Agent 检查以下条件全部满足：
  - .status.md 中 `执行轮次` >= 1 且（最近一轮为见证轮 或 `执行轮次` = 轮次上限 或 存在通过的复检轮）
  - 阶段产物文件存在且格式正确
  - traceability.md 对应列覆盖率 = 100%
  - 无 TODO/TBD/{待填写} 等占位符
- **THEN** 验收通过
- **AND** 更新 .status.md 中对应阶段状态为 ✅ 完成
- **AND** 门控释放，可进入下一阶段

#### Scenario: 验收不通过——无见证轮且未达上限

- **WHEN** 主 Agent 检查发现无任何一轮为见证轮 且 `执行轮次` < 轮次上限
- **THEN** 验收不通过
- **AND** 无见证轮且未达上限为硬性拒收条件，不接受 Agent 子代理任何理由的提前返回
- **AND** 系统记录到 skill-suggestion.md（包含阶段、当前轮次、轮次上限、建议：继续执行剩余轮次）
- **AND** 直接重新启动 Agent 子代理继续执行，不询问用户

#### Scenario: 验收不通过——终止点清单非空却未追加复检轮

- **WHEN** 主 Agent 在终止点发现累积未复核修复清单非空
- **AND** 系统未追加复检轮
- **THEN** 验收不通过
- **AND** 系统 SHALL 追加 1 轮复检轮后重新验收
- **AND** SHALL NOT 因 `执行轮次` = 轮次上限而跳过复检轮

#### Scenario: 验收不通过——达上限但产物不合格

- **WHEN** 主 Agent 检查发现 `执行轮次` = 轮次上限
- **AND** 不存在通过的复检轮
- **AND** 产物条件不满足（文件缺失、覆盖率不足、有占位符）
- **THEN** 验收不通过，进入非收敛分支
- **AND** 系统记录到 skill-suggestion.md（包含阶段、轮次上限、覆盖率缺口、建议）
- **AND** 使用 AskUserQuestion 询问用户：「验收不通过，是否重新启动重复制子代理？」
- **AND** 用户选择「是」→ 调整 prompt 后重新启动 Agent 子代理
- **AND** 用户选择「否」→ 标记 .status.md 为 ⚠️ 需修订，阻塞当前阶段

#### Scenario: 复检轮通过后验收通过

- **WHEN** 主 Agent 检查发现存在通过的复检轮
- **AND** 终止原因记录为 `收敛（复检轮）`
- **AND** 阶段产物文件存在且格式正确，覆盖率 = 100%，无占位符
- **THEN** 验收通过
- **AND** 更新 .status.md 中对应阶段状态为 ✅ 完成

#### Scenario: 验收记录格式

- **WHEN** 验收不通过并记录到 skill-suggestion.md
- **THEN** 记录 MUST 包含以下字段：发现时间、发现阶段（Agent 验收）、触发场景、覆盖缺口详情、轮次信息（当前轮次/轮次上限）、终止原因、复杂度信息、改进建议、状态（待重跑）、优先级
