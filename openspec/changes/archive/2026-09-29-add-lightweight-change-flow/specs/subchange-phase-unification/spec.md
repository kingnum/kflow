# Spec Delta

## MODIFIED Requirements

### Requirement: 子变更阶段统一为 5 阶段

系统 SHALL 将子变更的阶段列表统一为 5 个阶段：计划 → 编码 → 代码审查 → 接口单元测试 → E2E测试（kflow-e2e-test）。前后端项目执行全部 5 阶段，纯后端项目跳过 E2E测试。变更档位为 `轻量` 时，接口单元测试与 E2E测试 SHALL 按阶段适用性声明条件适用，可标记为 `⏭️ 不适用`。测试阶段包含「等待变更级同步」状态，确保子变更在每轮测试间批量同步。

#### Scenario: 前后端项目子变更阶段

- **WHEN** 项目类型为前后端项目 且 变更档位为 `标准` 或 `完整`
- **THEN** 子变更阶段依次为：计划 → 编码 → 代码审查 → 接口单元测试 → E2E测试（kflow-e2e-test）
- **AND** 所有 5 个阶段均需执行

#### Scenario: 纯后端项目子变更阶段

- **WHEN** 项目类型为纯后端项目
- **THEN** 子变更阶段依次为：计划 → 编码 → 代码审查 → 接口单元测试
- **AND** E2E测试阶段标记为 ⏭️ 跳过

#### Scenario: 轻量档子变更阶段条件适用

- **WHEN** 变更档位为 `轻量`
- **THEN** 接口单元测试阶段 SHALL 在阶段适用性声明判定为适用时执行，否则标记为 `⏭️ 不适用`
- **AND** E2E测试阶段 SHALL 在阶段适用性声明判定为适用时执行，否则标记为 `⏭️ 不适用`
- **AND** 计划、编码、代码审查三个阶段 SHALL 恒执行，不受裁剪影响

#### Scenario: 子变更测试阶段的批量同步状态

- **WHEN** 子变更完成当前轮次 E2E 测试或接口单元测试
- **THEN** 如其他子变更仍在执行或修复中，该子变更进入「等待变更级同步」状态
- **AND** 状态标记为 ⏸️ 等待同步
- **AND** 不自行推进到下一轮

#### Scenario: 无测试阶段可执行时跳过同步

- **WHEN** 变更档位为 `轻量` 且 接口单元测试与 E2E测试均标记为 `⏭️ 不适用`
- **THEN** 子变更在代码审查完成后 SHALL 直接进入变更级同步点，SHALL NOT 进入「等待同步」状态
- **AND** 该子变更加入变更级同步的判定，不阻塞其他子变更的同步推进

#### Scenario: 等待同步后进入下一轮

- **WHEN** 变更级 agent 完成服务编译重启并通知进入下一轮
- **THEN** 子变更从「⏸️ 等待同步」转为「🔄 进行中」
- **AND** 开始执行 Round N+1 测试
