# Design

## Context

探索阶段产物 `functional-designs/index.md` 现为 §一~§八 结构（变更概述 / 功能点清单 / 功能结构树 / 核心业务流程图 / 功能点依赖关系图 / 分册总览 / 配置项影响矩阵 / 修订记录）。页面信息仅存在于 `part-NN.md` 各 FP 的「所属页面与菜单」表；NFR 后置到 `kflow-design` 步骤 6，输入无探索侧来源。约束：

- **阶段边界**（`phase-boundary-enforcement`）：explore 内容聚焦用户视角，禁止技术目标值定义
- **结构性章节不省略**：无内容时标注「无」，不删除章节
- **轻量档不改动探索流程**：不新增/跳过步骤，仅压缩产出形态
- **收敛门自调节**：门槛强度由真实歧义量决定，不按档位分级

## Goals / Non-Goals

**Goals:**

- 定稿两个新内容承载的结构、落点与章节编号方案
- CLARIFY 五域→六域扩展在全部权威落点（设计文档、SKILL.md、explore 专属 reference）保持一致
- 打通下游消费闭环：design 阶段 NFR 章节显式声明输入来源
- 自审完整性检查项同步扩展

**Non-Goals:**

- 不新增流程步骤（CLARIFY/SPLIT/TIER 步骤骨架与编号不变）
- 不修改 `kflow-prototype-design`（页面清单经 functional-designs 自然流入其输入）
- 不修改 `part-NN.md` 分册模板（FP 级字段不变）
- 不输出视觉稿/交互原型（仍属 prototype 阶段）
- 不定义技术目标值（并发数、P95 等仍由 design 阶段 NFR 章节定义）

## Decisions

### D1: 非功能期望为 §一 内的小节，不独立成章

落在「变更概述」下，与问题描述/目标用户/预期价值同级。理由：它是概述性需求输入，语义同类；避免抬升章节层级导致 §二~§八 全部重编号。替代方案（独立章节）被否——层级过重、波及面大。

表结构：期望维度（开放枚举：性能感受/安全与合规/可用性/兼容性/其他）| 期望描述（用户语言）| 关联功能点。无期望时整节标注「本变更无特殊非功能期望」。

### D2: 页面清单置于功能结构树之后，后续章节顺延重编号

结构树（模块→FP 视角）与页面清单（页面→FP 视角）相邻构成互补视图对，同供 prototype（页面/功能全景）与 design（技术分组）消费。重编号：新 §四 页面清单，原 §四~§八（流程图/依赖图/分册总览/配置项矩阵/修订记录）顺延为 §五~§九。

替代方案（置于 §二 功能点清单之后）被否——清单与树相邻更自然，页面清单与树是视角互补对。波及控制：apply 时全仓 grep 旧章节号引用（如「八、修订记录」）同步更新；分册模板不受影响。

表结构：页面名称 | 菜单路径 | 类型（新建/修改/复用）| 页面结构描述（区块级文字）| 涉及功能点。纯后端项目或无前端 FP 时标注「本变更无涉及页面」。

### D3: 六域扩展采用「枚举表加行」，不新增独立采集步骤

CLARIFY 遍历域在既有五域表上加第 6 行「非功能期望：用户视角的性能/安全/可用性/兼容期望是否明确且无歧义」，同步修改两处「五个内容域」措辞为六个（`clarify-convergence.md` §1.1 正文与空清单凭据、§六 对比表）。理由：保持「产物章节 ↔ 澄清遍历域」机制一致性——模板有节、采集有门。替代方案（独立采集步骤，不动收敛门）被否——采集无门，模板节会沦为无人填充的摆设。

同步落点：`kflow-explore.md` 设计文档 CLARIFY 章节候选清单规则、SKILL.md 6b 域清单与 6c 候选来源。

### D4: 期望维度枚举开放，不与 NFR 四子节硬绑

design 阶段 NFR 的性能/安全/可用性/可维护性是技术分类；用户期望维度（如兼容性、易用性感受）不必一一映射。枚举提供常用维度 + 「其他」，转译映射由 design 阶段执行。

### D5: 下游消费为「一行输入说明」

`kflow-design.md` 步骤 6（NFR）描述补一句输入来源；`detailed-design.md` 模板 §三 头部加「需求输入：functional-designs/index.md『非功能期望』小节」说明行。不新增规格章节、不改 NFR 四子节结构。探索侧标注「无特殊非功能期望」时按既有最小要求自行定义（见 nfr-requirements delta）。

### D6: 自审仅完整性加一项检查

`self-review-dimensions.md` 完整性表加一行「页面清单一致性：页面清单与各 FP 所属页面一致（无孤页/漏页）」。非功能期望不新增检查项——空值合法性由「标注『无』」规则约束，占位符由产物完整性门控兜底，避免检查维度膨胀。

### D7: 轻量档单页纳入两节最小形态

轻量档单页压缩形态由「功能点清单+影响分析+修复/实现范围」扩为「…+非功能期望（一行，无则标注）+页面清单（简表或『无』标注）」。结构描述可合并为一句；不因轻量档省略章节（结构性章节不省略规则）。TIER/OUTPUT 步骤的轻量档描述两处（设计文档、SKILL.md）同步。

### D8: 顺带修复设计文档与 SKILL.md 的域内内容表措辞偏差

现状：设计文档「域内内容」表列「功能结构树」而无「页面结构/菜单层级」，SKILL.md 同表反之。apply 时统一为同一张表（含页面结构/菜单层级、非功能期望、页面清单），消除双源偏差。

## Risks / Trade-offs

- [六域抬高澄清成本] → 收敛门强度自歧义量自调节：无期望歧义时该域遍历为空、成本近零；缺陷级简化流程同样适用
- [页面清单与功能结构树信息重复] → 分工明确（模块视角 vs 页面视角）；清单聚合 FP 既有页面归属，结构描述为唯一新增信息量，每页一行成本可控
- [章节重编号导致引用断裂] → apply 时全仓 grep 旧章节号（「四、核心业务流程图」「八、修订记录」等）并同步更新
- [轻量档单页膨胀] → 两节最小形态（一行/简表），总增量不超过数行
- [用户期望含技术数值造成边界模糊] → 允许记录用户原意并标注口径来源，禁止转写为可度量目标值（specs 已约束）

## Migration Plan

无数据迁移。存量变更的 functional-designs 不回填——新章节仅对新变更生效；REVISION 模式修订存量文档时按需增补（增补属用户指定修订范围）。归档时 `requirement-clarification` 能力行为变更，预计 minor 位 +1（由归档后规则判定）。
